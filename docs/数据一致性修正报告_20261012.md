## 三、⚠️ 执行中发现：`codex_group` 上的触发器会改写 `date_edit`

库中存在如下触发器（原文）：

```sql
CREATE TRIGGER update_codex_group_modtime
AFTER UPDATE ON codex_group
FOR EACH ROW
BEGIN
    UPDATE codex_group SET date_edit = CURRENT_TIMESTAMP WHERE codex_id = OLD.codex_id;
END
```

**第一次写库的影响**（792 次 `ship_aid` UPDATE 全部触发该触发器）：

- 512 行原本为空的 `date_edit` 被写成本次运行时间
- 313 行真实编辑时间被覆盖
- `Collab077` 的 `22025` 笔误修正被覆盖

**处理方式**：

1. 把被改写的中间状态留档为 `..._after_bad_normalize.db`（便于事后比对）
2. 用**写库前快照**回滚数据库文件（回滚后 `date_edit` 空值恢复为 594 行、`ship_aid` 待归一化恢复为 792 条）
3. 以「触发器感知」方式重做：单事务内 **`DROP TRIGGER` → 归一化 → 原样 `CREATE TRIGGER`**（SQLite 的 DDL 参与事务，失败即整体回滚）
4. 顺带恢复 `Plan042` 的编辑时间 —— 上一轮「科技数据修正」改名时同样触发了该触发器，
   把它从 `2025-08-12 20:51:46` 改成了当时的运行时间，本次恢复为原值

## 七、`codex_id` 存储类型：核查结论（**不转换**）

| 表 | 存储类型分布 |
| --- | --- |
| `codex_group` | integer: 691，text: 308 |
| `codex_tp` | integer: 1941，text: 339 |
| `codex_buff` | integer: 2127，text: 454 |

**核查**：同一舰娘在三张表中的存储类型**完全一致**（`codex_tp` / `codex_buff` 与
`codex_group` 的 JOIN 结果为 2280 / 2581 行，**零漏行**），因此现有代码（`str()` + `CAST`）
功能正常，不存在隐性丢行风险。

**不转换为纯 TEXT 的原因**：`findLocked()` / `findUnlocked()` / `findAwakenable()` 等均使用
`ORDER BY ship_aid DESC, codex_id DESC`。SQLite 对混合类型按「存储类」排序，当前形态下
数字 id 按**数值**排序、`META…` / `Refit…` 等文本 id 排在其后；一旦全部转成 TEXT，
数字 id 会退化为字典序（`99` 排在 `100` 之前），反而破坏列表顺序。

**结论**：维持现状；如将来要做彻底统一，必须同时改为按数值排序（例如 `CAST(codex_id AS INTEGER)`
或新增数值排序键）。

## 十、触发器改为本地时间（2026-10-13）

**背景**：第三节记录的 `codex_group` 触发器把 `date_edit` 写为 `CURRENT_TIMESTAMP`（UTC，比本地早 8 小时），
而录入对话框写入的是本地时间，导致同一字段混存两种时区。

**处置**：仅替换触发器定义（DDL 不触发 `AFTER UPDATE`，**0 行数据被改写**）。

```sql
-- 修改前
CREATE TRIGGER update_codex_group_modtime
AFTER UPDATE ON codex_group
FOR EACH ROW
BEGIN
    UPDATE codex_group SET date_edit = CURRENT_TIMESTAMP WHERE codex_id = OLD.codex_id;
END;

-- 修改后
CREATE TRIGGER update_codex_group_modtime
AFTER UPDATE ON codex_group
FOR EACH ROW
BEGIN
    UPDATE codex_group SET date_edit = datetime('now','localtime') WHERE codex_id = OLD.codex_id;
END;
```

**验证**

| 检查项 | 结果 |
| --- | --- |
| 触发器定义 | 已含 `datetime('now','localtime')`，不再含 `CURRENT_TIMESTAMP`；触发器数量 1 |
| `date_edit` / `ship_level` / `ship_star` 变化行数 | **0**（DDL 不改数据） |
| 在临时副本上触发一次 UPDATE | 写入 `2026-10-13 22:51:13`，与本地时间差 **0 秒**，与 UTC 差 **28,800 秒（8 小时）** → 确认写入本地时间 |
| 写库前快照 | `data/backup/AzurLaneStatisticalOfficeDB_20261013_pre_trigger_localtime.db` |

**历史值说明**：`date_edit` 目前**只写不显示**（仅 `codex_ship_create_dialog` 写入，界面任何位置都不展示），
因此历史值中"对话框写入的本地时间"与"早期触发器写入的 UTC 时间"的混存不可见、也不影响任何功能，
本次**不做历史值转换**（无法可靠区分两者）。如需按时间排序或未来在界面上展示，建议届时再评估。

> 该触发器定义只存在于数据库内，未纳入版本库（`.gitignore` 含 `*.db`）；本报告保留其定义，供数据库重建时参照。
