# 日常建造任务两笔明细 + 档期右边缘对齐（2026-10-25）

## 1. 背景与目标

看板上「日常任务·建造舰船 1 次」单击只写一笔 `收入 · 日常任务 +1`，与真实玩法不符：
建造本身要扣魔方（轻型 1 / 重型、特型、活动 2），只是任务奖励把 1 个魔方还回来，
用建造券时则不扣魔方。

本次目标：

1. 单击建造卡片先弹确认框，选卡池（或勾选用券），一次落两笔明细（券抽只有收入）；
2. 魔方看板「档期」下拉右边缘对齐「任务」分组右边缘；红尖尖看板沿用同尺寸的下拉。

## 2. 口径

### 2.1 建造任务（`cube_task.daily_build_once`）

| 选择 | 支出明细 | 收入明细 | 活动联动 |
|---|---|---|---|
| 轻型 | `支出 · 轻型建造 1` | `收入 · 日常任务 1` | 不关联 |
| 重型 / 特型 | `支出 · 重型/特型建造 2` | 同上 | 不关联 |
| 活动 | `支出 · 活动建造 {进行中活动单耗}`（无进行中活动时 2） | 同上 | 明细写 `event_id`，按「关联魔方 ÷ 单耗」计入活动建造次数 |
| 使用建造券 | 无 | 同上（备注标「建造券」） | 进行中活动 `ticket_build_count +1`、`use_ticket=1` |

补充规则：

- 两笔明细同一时刻（点击瞬间 `time_source.now()`，补录时为「所选日期 + 当前时分秒」），同一事务提交；
  当日汇总 `upsertDetailDaily` 与末次时刻只维护一次。
- 「进行中活动」取 `status = 进行中` 中 `event_date DESC, id DESC` 的第一条，与常规录入默认值一致。
- 未勾选建造券时卡池单选项生效；勾选后卡池置灰（券不消耗魔方，池型不再影响扣减）。
- 通用完成入口 `completeTask` 对建造任务直接报错，防止绕过确认框写出「只有收入」的不一致数据。

### 2.2 取消

- 删收入 + 删支出（有的话）+ 删完成记录，重算当日末次时刻。
- 券抽记录（`expense_transaction_id IS NULL AND event_id IS NOT NULL`）额外把该活动
  `ticket_build_count -1`（下限 0，归零时清 `use_ticket`）。
- 支出被手工删除时容错：只清理剩余行，提示「关联明细已不存在」。

### 2.3 撤销上一笔

`findLatestManualTransaction` 改为 `NOT EXISTS` 同时排除 `transaction_id` 与
`expense_transaction_id`，否则建造支出会被当成常规录入撤销掉
（`repositories/resource_repository.py:309`）。

### 2.4 活动页建造次数

`EventRecordService._buildView` 原先只在「有关联魔方明细」时折算，纯券抽会被丢掉。
现改为（`services/event_record_service.py:181`）：

- 有明细：`关联魔方 ÷ 单耗 + 券抽`（不变）；
- 无明细但有券抽：`手工 / 历史值 + 券抽`，并标记为折算，tooltip 写明「手工值 N + 建造券 M 次」。

## 3. 交互

`views/dialogs/build_task_dialog.py`：

- 标题行：任务名 + 记账时刻 + 任务奖励；
- 「卡池」单选：轻型建造（-1）/ 重型建造（-2）/ 特型建造（-2）/ 活动建造（-单耗），默认轻型；
- 复选框「使用建造券（不扣魔方）」：勾选后卡池置灰；
- 预览区实时写明「将写入 2 笔 / 1 笔」，活动场景写出关联哪个进行中活动；
- 按钮：确认记两笔 / 取消。

卡片 tooltip：未完成时提示「单击选择卡池」；完成后显示「支出 · 轻型建造 1 + 收入 · 日常任务 1」，
券抽显示「使用建造券（不扣魔方）」。双击取消的确认框会列出将删除的两笔。

## 4. 结构变更

`cube_task_completion` 增两列（可空，历史行保持 NULL）：

| 列 | 用途 |
|---|---|
| `expense_transaction_id` | 建造支出明细 ID；NULL 表示没有支出 |
| `event_id` | 本次关联 / 计入券抽的活动 ID；NULL 表示没有进行中活动 |

- 新库：`sql/CreateCubeTaskTables.sql` 直接建列；
- 旧库：`utils/db_schema.py:123` 按「列是否存在」补列，可重复执行；
- 不新增表、不重建、不动历史快照表。

## 6. 档期右边缘对齐

- 头部由单行 `QHBoxLayout` 改为两段式 `QGridLayout`（`views/widgets/cube_task_board_panel.py:294`）：
  左段「记账日期 + 今天 + 弹性空白 + 档期 + 下拉」，右段「刷新 + 周期信息」，
  两段 stretch 1:1、列间距 12 与看板网格一致 ⇒ 下拉右边缘恒等于左列右边界，也就是「任务」分组的右边缘。
- 下拉尺寸统一为 `最小 120 / 最大 190 / 高 28`（`PERIOD_COMBO_*` 常量），空间不足时收窄但右边缘不漂移，
  避免真实字体下把头部撑出横向滚动条。
- 红尖尖看板复用同一实现（`compact_header=True`）：单列时右段隐藏，下拉取同一尺寸并贴住自身分组右边缘。
- 窄屏（看板单列）时头部退回两行（左段通栏 + 第二行刷新与周期信息），对齐关系仍成立。

## 8. 风险与后续

- **真实窗口观感未人工确认**：对话框间距、卡片 tooltip、窄屏两行头部需要 `python main.py` 目视。
- 真实字体下若左列空间紧张，魔方档期下拉会收窄到 120–190 之间，此时与红尖尖的宽度可能相差十几像素（对齐优先）。
- 活动页口径变化：无关联明细但有券抽时，建造次数 = 手工值 + 券抽；历史上依赖「无明细必为手工值」的判断需要留意。
- 取消券抽记录会把 `use_ticket` 归零，若用户此前手工开启过建造券开关，取消后需要手动再勾一次（已知取舍）。
- 补录到活动开始前的日期时，仍会关联「当前进行中」的活动（按点击时刻判定，不按记账日期回溯活动区间）；
  对话框预览会写明将关联哪个活动。
- 任务补录到 `summary_only` 历史日仍会翻成明细日并清空当日存储收支（既有行为，未在本次改动）。
