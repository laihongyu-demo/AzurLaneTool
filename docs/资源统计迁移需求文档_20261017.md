## 1. 背景与目标

### 1.1 现状

魔方、红尖尖、指级经验三类数据目前全部维护在 Excel 台账中，`碧蓝航线.xlsx` 与根目录 7 个 CSV 是导出副本。
数据库 `data/AzurLaneStatisticalOfficeDB.db` 中**不存在任何魔方 / 红尖尖相关的表或字段**，表清单仅有
`codex_group`、`codex_buff`、`codex_tp`、`awakening_of_mind`、`commander_info`、`level`、`task_status`
及若干图鉴备份快照表。

与指挥官相关的既有对象都没有被应用使用：

| 对象 | 现状 | 问题 |
| --- | --- | --- |
| `commander_info` | 371 行，列为 `id / statistics_date / commander_level / commander_exp` | 运行时代码**零引用**（全项目 grep 无读取方）；无索引；`statistics_date` 为 `yyyy/M/d HH:mm` 文本，字符串排序不可靠 |
| `level` | 0 行，只有 `level` / `level_edittime` 两列 | 历史遗留，语义上想表达"等级基准"但缺字段，实际未使用 |

因此 issue #14 的四张卡（指挥官等级 / 指级效率 / 魔方 / 红尖尖）自项目初始就是占位 `-`，
`StatisticsPanel.refreshData()` 只写入了「执勤天数」一张卡。

### 1.2 目标

1. **入库**：魔方、红尖尖、指级经验三类台账迁入 SQLite，数据库成为唯一事实源，Excel 退役。

4. **可维护**：指级经验快照可查、可改、可删；派生值（需求经验、进度）实时按基准表计算。

## 3. 口径定义

| 术语 | 定义 |
| --- | --- |
| 明细 | 一笔收入或支出：**发生时刻** + 方向 + 事件 + 数量（可选备注）。同一日期同一事件可有多笔 |
| 明细时刻（`record_time`） | `yyyy-MM-dd HH:mm:ss`，精确到秒；录入时可手填以支持补录，日期部分决定这笔记录归属哪一天 |
| 末次记录时刻（`last_record_time`） | 某日最后一笔明细的时刻，冗余在日汇总行上，供看板 tooltip 显示到秒 |
| 日汇总行 | 某资源某一天的记录载体，承载"模式、收入、支出、手填结余、备注、末次记录时刻" |
| 明细日（`detail`） | 该日存在明细，收入 / 支出 = Σ明细，不允许单独存数 |
| 汇总日（`summary_only`） | 该日无明细，收入 / 支出直接存储（魔方 2023-08-03～2024-10-15 的历史段即为此类） |
| 手填结余 | 用户填写的当日真实结余，作为累加锚点；留空则该日结余自动推导 |
| 结余 | 派生的累计值，**不落库** |

> **时刻精度说明**：原 Excel 台账只有日期，无时刻可考。因此迁移进来的 7162 条明细统一记为
> `<日期> 00:00:00`，展示层遇到 `00:00:00` 视为"仅有日期"，只显示日期；
> 只有今后新录入的记录才会显示真实时刻。**不为历史数据编造时间。**

### 3.1 结余计算

```
结余(首个日期之前) = 0
结余(d) = 手填结余(d)                      —— 若该日填写了手填结余
        否则  结余(上一个有记录的日期) + 收入(d) - 支出(d)
```

结余是派生值，查询时按日期顺序一次扫描得出（1827 行量级，开销可忽略）。
好处是**任何历史记录的增删改都不需要回写后续行**，不存在缓存失效问题。

### 3.2 迁移后的手填锚点（已全量验算）

| 资源 | 日期 | 原表结余 | 自动累计应为 | 差额 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 魔方 | 2023-08-03 | 3 | 6 | -3 | 首日起始库存 |
| 魔方 | 2023-09-15 | 175 | 126 | +49 | 断链（人工推导期） |
| 魔方 | 2023-11-09 | 252 | 488 | -236 | 断链（岛风复刻当日） |
| 魔方 | 2023-11-16 | 308 | 291 | +17 | 断链（人工推导期） |
| 魔方 | 2023-12-02 | 248 | 262 | -14 | 断链（人工推导期） |
| 红尖尖 | 2025-01-01 | 673 | 0 | +673 | 首日起始库存 |

验算方法：以以上 6 个锚点重设后逐日累加，**其余 1167 天魔方与 654 天红尖尖的结余与原表 100% 一致**（0 处偏差）。
因此这 6 个锚点就是全部需要人工介入的偏差，其余日期一律自动累加。

> 说明：魔方 2023 年中至 2024-10 的数据按用户描述属"人工推导、无原始依据"，本次迁移**不做数据修正**，
> 只按锚点保证后续链路自洽；溯源能力从 2024-10-16 起具备（明细可查）。

### 4.2 F-02 指级经验快照录入

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 记录时间 | `QDateTimeEdit`（`yyyy-MM-dd HH:mm`） | 默认当前时间；**禁止晚于当前时间** |
| 等级 | `QSpinBox` | 1 ～ 200，默认取最近一条记录的等级 |

- 保存后**追加**一条快照（历史快照语义，不覆盖旧记录）。
- 同一时间点不允许重复（唯一索引）；重复提交提示「该时间点已存在记录，请调整分钟数」。
- 保存成功后：刷新列表 → `dataRefreshed.emit()` → 主窗口刷新看板；状态栏给一句话反馈。

- `commander_info` 取最新一行的排序键必须是 `ORDER BY statistics_date DESC, id DESC`（时间已规范化，见 §6.2）。
- 旧库 / 空库 / 缺列时降级为 `-`，不得抛异常。
- 卡片**不提供**跳转与录入入口（#18 / #17）。
- 时刻展示口径：`last_record_time` 或该日明细最大时刻，取较晚者；时间部分为 `00:00:00`（历史占位）
  时只显示日期，避免让用户误以为真有凌晨记录。

### 4.5 F-05 魔方 / 红尖尖：本期的只读定位

- 数据只经**迁移**写入（§8），应用内没有任何写入口：视图层不引用 `resource_*` 的写方法，
  仓库层本期只实现读接口（取最新结余、按日期查询）。
- 结余由服务层按日期顺序扫描得出（含 6 个手填锚点），库中不存派生值。
- 迁移一并导入 `resource_category`（41 条事件字典）：CSV 删除后这些名称只存在于库中，
  是 #17 上线时下拉候选的唯一来源，**不得省略**这一步。
- 后续开放录入时只需增加面板与写接口，表结构无需再改。

## 5. 校验规则与异常处理

### 5.1 录入校验（本期仅指级经验）

| 编号 | 规则 | 触发时机 | 处理 |
| --- | --- | --- | --- |
| V-05 | 等级 1 ～ 200 | 控件层 | 阻断 |
| V-06 | 当前经验 ≤ 该等级本级所需经验 | 提交时 | 阻断，提示所需经验值 |
| V-07 | 快照时间不得重复 | 提交时 | 阻断，提示已存在 |
| V-08 | 快照时间不得晚于当前时间 | 提交时 | 阻断 |
| V-09 | 删除操作 | 点击删除 | 二次确认（`QMessageBox.question`） |

> V-01～V-04（日期不得晚于今天、数量范围、事件名非空、手填结余非负）属于魔方 / 红尖尖录入，
> 随该功能推迟，原文保留在附录 D，实施 #17 时直接沿用。

### 5.2 读路径的健壮性

- 卡片与面板读取时：表不存在 / 无数据 / 值为 `NULL` → 统一降级为 `-` 或空列表，不抛异常、不弹错误框。
- 若历史快照出现无法解析的时间格式（迁移后不应存在），该行跳过并记入日志，不让整个面板失败。

### 5.3 异常处理

- Repository 层捕获 `sqlite3.Error` 并转 `DatabaseError`；Service 层校验失败抛 `ValidationError`（沿用 `utils/exceptions.py`）。
- 视图层捕获后统一 `QMessageBox` 提示 + 状态栏文字，禁止把 SQL 异常原文抛给用户。
- 事务：本期写操作是「快照的插入 / 更新 / 删除」，单条写也需走 `DatabaseContext`（异常自动回滚）；
  迁移脚本（§8）整体单事务。

## 6. 数据模型（方案建议）

### 6.1 新增表

```sql
-- 日汇总行：明细日只存模式与锚点，汇总日才存收支
CREATE TABLE IF NOT EXISTS resource_daily (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    resource_type    TEXT NOT NULL CHECK (resource_type IN ('cube', 'red_gem')),
    record_date      TEXT NOT NULL,                 -- yyyy-MM-dd
    detail_mode      TEXT NOT NULL DEFAULT 'detail'
                     CHECK (detail_mode IN ('detail', 'summary_only')),
    income           INTEGER,                       -- 仅 summary_only 使用；detail 模式为 NULL
    expense          INTEGER,                       -- 同上
    balance_override INTEGER CHECK (balance_override IS NULL OR balance_override >= 0),
    note             TEXT NOT NULL DEFAULT '',
    last_record_time TEXT,                          -- 该日最后一笔的时刻；历史数据为 NULL/占位
    created_at       TEXT NOT NULL DEFAULT (datetime('now', 'localtime')),
    updated_at       TEXT,
    UNIQUE (resource_type, record_date),
    CHECK (
        (detail_mode = 'summary_only' AND income IS NOT NULL AND expense IS NOT NULL)
     OR (detail_mode = 'detail'       AND income IS NULL     AND expense IS NULL)
    )
);

-- 明细：一笔收入或支出
CREATE TABLE IF NOT EXISTS resource_transaction (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    resource_type TEXT NOT NULL CHECK (resource_type IN ('cube', 'red_gem')),
    direction     TEXT NOT NULL CHECK (direction IN ('income', 'expense')),
    record_time   TEXT NOT NULL,                    -- yyyy-MM-dd HH:mm:ss，可手填以补录
    category      TEXT NOT NULL,                    -- 来源 / 去向名称
    amount        INTEGER NOT NULL CHECK (amount > 0),
    note          TEXT NOT NULL DEFAULT '',
    created_at    TEXT NOT NULL DEFAULT (datetime('now', 'localtime')),
    updated_at    TEXT
);

-- 事件字典
CREATE TABLE IF NOT EXISTS resource_category (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    resource_type TEXT NOT NULL CHECK (resource_type IN ('cube', 'red_gem')),
    direction     TEXT NOT NULL CHECK (direction IN ('income', 'expense')),
    name          TEXT NOT NULL,
    sort_order    INTEGER NOT NULL DEFAULT 0,
    UNIQUE (resource_type, direction, name)
);

-- 等级 → 升级所需经验基准（由 data/commander_level.csv 导入）
CREATE TABLE IF NOT EXISTS commander_level_exp (
    level          INTEGER PRIMARY KEY CHECK (level BETWEEN 1 AND 200),
    level_up_exp   INTEGER CHECK (level_up_exp IS NULL OR level_up_exp > 0),
    cumulative_exp INTEGER CHECK (cumulative_exp IS NULL OR cumulative_exp > 0),
    note           TEXT NOT NULL DEFAULT ''          -- 如「当前版本最高等级」
);

CREATE INDEX IF NOT EXISTS idx_resource_transaction_time
    ON resource_transaction (resource_type, record_time);
-- resource_daily 已有 UNIQUE (resource_type, record_date)，无需重复建索引
CREATE UNIQUE INDEX IF NOT EXISTS uq_commander_info_date
    ON commander_info (statistics_date);
```

> 旧库（明细列仍为 `record_date`、日汇总缺 `last_record_time`）由 `utils/db_schema.py` 的
> `_upgradeLegacySchema()` 在应用启动时幂等升级：`RENAME COLUMN` → 补 ` 00:00:00` → `ADD COLUMN` → 回填。
> 因此无需手工执行迁移 SQL，也不会因版本差异启动失败。

### 6.2 复用与清退

| 对象 | 处理 |
| --- | --- |
| `commander_info` | **复用**。补导 151 条缺失记录；`statistics_date` 全量规范为 `yyyy-MM-dd HH:mm`；建索引 |
| `level` | **清退**（0 行、无引用）。删除前在迁移报告中留档原 DDL |
| `data/commander_level.csv` | 导入 `commander_level_exp` 后转为**可选**的外部副本；是否保留该文件见 §11 待确认 |

`commander_info` 不改表结构，仅做数据规范化。规范化由迁移脚本逐行解析时间字符串后**参数化**写回：

```sql
-- 由脚本逐行解析后执行，不使用 SQL 字符串函数拼接
UPDATE commander_info SET statistics_date = ? WHERE id = ?;
-- 全部规范化后，为「取最新一行」建立唯一索引
CREATE UNIQUE INDEX IF NOT EXISTS uq_commander_info_date
    ON commander_info (statistics_date);
```

若唯一索引建立失败（存在重复时间戳），迁移脚本必须中止并报告冲突行，不得静默跳过。

### 6.3 设计取舍

| 问题 | 选择 | 理由 |
| --- | --- | --- |
| 日汇总做视图还是表 | **表** | 魔方 440 天的历史段没有任何明细，视图无法还原总量；表才能同时承载"有明细"和"只有汇总"两种事实 |
| 结余是否落库 | **不落库** | 落库就要在每次增删改后级联回写，易产生不一致；派生计算量极小 |
| 历史汇总段是否合成假明细 | **不合成** | 合成会让"明细"里出现 800+ 条无来源的伪记录，破坏明细的可信度，也会污染事件统计 |
| 明细与汇总是否分表（魔方/红尖尖各一套） | **单表 + `resource_type`** | 两者结构完全一致，一套 Repository/Service 即可复用，后续接石油/物资零成本 |
| 是否加"实际获得"列 | 不加 | 可由 `收入 - 支出` 派生 |

## 9. 非功能需求

| 编号 | 需求 |
| --- | --- |
| N-01 | 性能：看板刷新（结余扫描 1827 行 + 明细 7162 行）应在 200 ms 内完成；指级经验列表默认只查最近 30 条 |

## 附录 D 推迟需求：魔方 / 红尖尖 录入与编辑（本期不实现）

> 本附录完整保留需求原文，供 #17 实施时直接使用。**本期任何一条都不实施**，
> 表结构与迁移数据已就绪，届时无需再改库。

### D.1 面板结构

- 「资源统计」页签内新增魔方 / 红尖尖两个面板：**同一控件的两次实例化**（仅 `resource_type`、显示名、事件字典不同）。
- 每个面板自上而下：当前结余（精确千分符，与看板卡片的大概数值区分）→ 录入表单 → 当日汇总 / 手填结余 → 历史列表 + 查询。

### D.2 明细录入

| 字段 | 控件 | 规则 |
| --- | --- | --- |
| 发生时刻 | `QDateTimeEdit`（`yyyy-MM-dd HH:mm:ss`，日历弹出 + 时分秒微调） | 默认当前时间；**禁止晚于当前时间**（V-01）；**允许手填更早时刻以补录**（例如今天补录昨天发生的记录），日期部分决定归属哪一天 |
| 方向 | `QComboBox`：收入 / 支出 | 必选，默认"收入" |
| 事件 | `QComboBox` + `setEditable(True)` | 候选来自 `resource_category`（按资源 + 方向过滤）；可直接输入新名称，保存时自动登记进字典 |
| 数量 | `QSpinBox` | 范围 1 ～ 1,000,000，默认 1（V-02） |
| 备注 | `QLineEdit` | 可选，≤ 200 字 |

- 点击「添加」：写入一条明细（含手填时刻）→ 自动维护该日的日汇总行（`detail` 模式），并把该日
  `last_record_time` 更新为「当前值与该条时刻中的较晚者」→ 刷新结余、列表、看板。
- **同一日期同一事件允许重复录入若干笔**（源数据最多 17 笔/日/事件），不做去重。
- 新增成功后在状态栏给出一句话反馈，样式对齐 `UnlockResult.toStatusBarMessage()`。

### D.3 日汇总与手填结余

- 日期选择器切换时预览该日：收入 / 支出 / 结余，并标注是「明细日（N 笔）」还是「汇总日」。
- **手填结余**为可选输入（V-04：非负整数）：
  - 填写 → 该日成为锚点，结余按 §3.1 重设；日期旁显示锚点标记；
  - 清空 → 恢复自动累加。
- 汇总日允许直接编辑收入 / 支出（这两列是该模式下的事实源）；明细日的收入 / 支出**只读**，由明细决定。

### D.4 历史列表

| 列 | 内容 |
| --- | --- |
| 日期 | `yyyy-MM-dd`，倒序 |
| 末次记录 | `last_record_time`；仅日期时显示 `—` |
| 收入 / 支出 | 明细日显示 Σ明细，汇总日显示存储值 |
| 结余 | 派生值；锚点日加标记（如 `◆`） |
| 笔数 | 明细笔数；汇总日显示 `—` |
| 备注 | 单元格内截断，悬停显示全文 |
| 模式 | `明细` / `汇总` |

- 查询：起止日期 + 是否包含"零收支日期"（红尖尖 223 天收支均为 0）；默认最近 30 天，可切全量。
- 操作：选中行后底部「编辑」「删除」；或双击行编辑。
- 至多 1172 行，`QTableWidget` 一次载入即可，无需分页。

### D.5 编辑与删除

| 操作 | 行为 |
| --- | --- |
| 编辑明细 | 弹窗改时刻 / 事件 / 数量 / 备注；**方向不可改**（改方向等价于删除后重建）；改时刻会同步维护新旧两天的 `last_record_time` |
| 编辑汇总日 | 弹窗改收入 / 支出 / 备注 / 手填结余 |
| 删除明细 | 二次确认；删除后若该日不再有明细，转为 `summary_only` 且收支置 0，备注追加"原明细已全部删除（YYYY-MM-DD）" |
| 删除日行 | 二次确认，提示"将同时删除该日 N 笔明细，后续结余会重新计算"；级联删除明细与日汇总行 |

### D.6 模式转换确认（`summary_only` → `detail`）

在汇总日新增明细时提示：

> 该日期当前按汇总记录：收入 X / 消耗 Y。转为明细后，收支将由明细自动汇总，原汇总值仅保留在备注中。
> 是否继续？

确认后：写入明细 → 日汇总行 `detail_mode` 置 `detail` → 原收入 / 支出清空 → 备注追加「原汇总：收入 X / 消耗 Y」。
