# 舰队位置字段与舰种修正（2026-10-25）

## 一、背景

`codex_group` 只记录 `ship_typ`（舰种），无法直接按游戏内的舰队编成区分**前排先锋 / 后排主力 / 水下舰队**。
本次为该表新增 `fleet_position` 字段并按舰种回填，同时修正初筛中发现的 11 条舰种录入错误。

口径来源：用户审核确认（2026-10-25 20:58）。

## 二、口径

| 位置 | 舰种 |
|---|---|
| 前排先锋 | 驱逐舰、轻型巡洋舰、重型巡洋舰、超级巡洋舰、弹药运输舰、风帆V |
| 后排主力 | 战列舰、战列巡洋舰、航空战列舰、航空母舰、轻型航空母舰、浅水重炮舰、维修舰、风帆M |
| 水下舰队 | 潜艇、潜水空母、风帆S |

审核要点：

- 浅水重炮舰 → 后排（游戏内低耗后排）；
- 弹药运输舰 → **前排**（占先锋位）；
- 维修舰 → 后排；
- 风帆V/M/S → 前排 / 后排 / 潜艇（V=Vanguard、M=Main、S=Submarine）；
- 潜水空母 → 水下舰队。

映射的**唯一来源**是 `utils/codex_options.py` 的 `SHIP_TYP_FLEET_POSITION` + `getFleetPosition()`，
迁移回填、新增舰娘派生共用这一份，不出现第二套口径。

## 三、表结构变更

```sql
ALTER TABLE codex_group ADD COLUMN fleet_position STRING(32);
```

- 由 `utils/db_schema.py` 的 `ensureCodexGroupSchema()` 完成：**列不存在才补**，随后只对空值按舰种回填，
  不覆盖已有结果，可重复执行；表不存在（全新/测试库）时直接跳过，不建表。
- `main.py` 启动时在 `ensureResourceStatisticsSchema()` 之后调用，失败只打印警告、不阻断启动。
- 模型、仓储、新增舰娘服务同步：
  - `models/codex_model.py`：`CodexGroupModel.fleet_position`；
  - `repositories/codex_repository.py`：12 处显式列清单 + `insert` / `update` 增加该列；
  - `services/codex_ship_create_service.py`：新增时按 `ship_typ` 派生（并校验舰种必须属于 `SHIP_TYPS` 白名单，
    从入口杜绝 `轻型航母舰` 这类错字），SQL 预览同步。

## 四、⚠️ 触发器陷阱

`codex_group` 上存在：

```sql
CREATE TRIGGER update_codex_group_modtime
AFTER UPDATE ON codex_group
FOR EACH ROW
BEGIN
    UPDATE codex_group
    SET date_edit = datetime('now','localtime')
    WHERE codex_id = OLD.codex_id;
END
```

任何 UPDATE 都会把 `date_edit` 改写为当前时间。回填 1004 行、修正 11 行都会命中它，
若不处理会把全表历史编辑时间刷成本次运行时间（2026-10-12 已踩过一次）。

处理方式：`utils/db_schema.suspendCodexGroupModtimeTrigger()` —— 在同一事务内
`DROP TRIGGER` → 写入 → 原样重建（SQLite 的 DDL 参与事务，失败整体回滚）。
`ensureCodexGroupSchema()` 与 `tools/fix_codex_ship_typ.py` 都已接入。

## 八、遗留风险

1. **常规舰种本身未逐条核对**：本轮只核对了「派生舰 vs 原型」「错字值」两类可自动发现的错误，
   常规舰娘的 `ship_typ` 没有第二数据源交叉验证；`codex_buff.boost_typ` 是**增益目标舰种**（如
   重巡 → 重巡/重炮/超巡），不能用来反证舰种，未作为校验依据。
2. **位置是冗余派生字段**：唯一维护点是「新增舰娘」与「补列回填」。若今后直接改库里的 `ship_typ`，
   位置不会自动跟随，需重跑 `ensureCodexGroupSchema()` 或手工同步。界面暂未展示/筛选该字段。
3. **未登记舰种留空**：`getFleetPosition()` 对白名单外舰种返回 `None`，位置保持空串（显示为未分类），
   不猜位置；游戏新增舰种时需同步 `SHIP_TYPS` 与 `SHIP_TYP_FLEET_POSITION`。
4. 附带发现（未处理）：`META066 灵敏·META` 的 `ship_aid` 为未来日期 `2027/10/01`，疑似笔误。
