## 1. 目标与边界

### 1.1 要解决的问题

「数据看板 → 指级效率」这张卡从项目开始就是占位 `-`，因为**口径从未定义**。本期只需要：

1. 定义一条可解释、可复现的口径；
2. 卡片显示一个数（如 `11,336/天`）；
3. tooltip 说清这个数是怎么来的；
4. 数据不足时优雅降级为 `-`，不抛异常。

### 1.2 明确不做

| 不做 | 原因 |
| --- | --- |
| 逐日落库 `daily_exp_efficiency` 表 | 卡片只需一个数；524 条快照全量在内存里算只要毫秒级 |
| λ 指数衰减预测 | 那是"预测未来效率"，与卡片"当前效率"的语义不是一回事；而且预测值无法被用户证伪 |
| MAD 异常检测 / 趋势切换状态机 | 见 §3.2，经验增长本身波动 3.5 倍，剔除会把真实的活动日误判成异常 |
| 缺口的每日均摊插值 | 见 §3.3，均摊会制造"虚假平滑"，让用户以为每天都在稳定产出 |
| QThread 异步计算 | 数据量太小，异步只会增加状态同步的麻烦 |

## 2. 数据现状（实测）

### 2.1 快照

| 项 | 值 |
| --- | --- |
| 快照数 | 524 条 |
| 首条 | 2023-08-09 10:12（70 级，当前经验 5,157） |
| 末条 | 2026-10-18 14:01（163 级，当前经验 105,302） |
| 时间跨度 | 1,166 天 |
| 同一天多条 | 213 组相邻记录间隔为 0 天（约占 40%） |
| 相邻间隔分布 | 0 天 213、1 天 203、2 天 43、3 天 15、4 天 18、5 天 9，长尾到 14 天 |

**结论**：快照不规则，既有同日多条，也有十几天空档，因此算法必须能处理"稀疏 + 重复"。

### 2.2 等级经验基准

`commander_level_exp` 共 200 行。实测 **198 个等级全部满足**：

```
cumulative_exp(L) - cumulative_exp(L-1) == level_up_exp(L)
```

抽样：

| 等级 | 本级所需 `level_up_exp` | 累计 `cumulative_exp` |
| --- | --- | --- |
| 1 | 50 | 50 |
| 2 | 60 | 110 |
| 3 | 70 | 180 |
| 162 | 346,200 | 11,214,610 |
| 163 | 354,350 | 11,568,960 |
| 199 | 752,250 | 31,046,860 |
| 200 | NULL | NULL |

**口径确认**：`cumulative_exp(L)` = 从 1 级累计到"升入 L+1 级"所需要的经验总量。
即 `cum(L)` 是**升级门槛**，不是"到达 L 级时已经拿到的经验"。

### 2.3 日增波动（全量，仅统计相邻自然日）

| 统计量 | 值 |
| --- | --- |
| 样本 | 350 天 |
| 最小 | 551 |
| P25 | 5,079 |
| 中位数 | 8,935 |
| P75 | 13,137 |
| 最大 | 31,121 |
| 均值 | 9,549 |

**结论**：最大值是最小值的 56 倍，P75 是 P25 的 2.6 倍。这个分布决定了 §3.2 的判断——
用"异常检测 + 裁剪"处理它，等于把真实的活动期抹平。

| 同日多条只保留最后一条 | ✅ 与"每日统计一次"的业务习惯一致，且不丢经验（最后一条的绝对值已包含当日全部增量） |
| 段内效率 = 增量 ÷ 间隔天数 | ✅ 定义正确 |
| 时间排序后处理 | ✅ 必须 |

### 3.2 不能沿用的部分

| # | 问题 | 证据 / 说明 |
| --- | --- | --- |
| 1 | **关键定义表在文档里是空的** | 「表1 字段定义」「表2 字段定义」「业务含义说明」「示例」四个小节只剩标题，`cumulative_required_exp` 的确切语义无从恢复。本文改用实测反推（§2.2） |
| 2 | **"累计"的定义自相矛盾** | 文档说 `cumulative_required_exp` 是"从 1 级开始累计获得多少经验后可以从当前等级升级到下一级"，但公式又写 `level_start_cum_exp(level) = cumulative_required_exp(level-1)`——前者暗含"含本级"，后者要求"不含本级"。实测表明后者才对 |
| 3 | **没有满级处理** | 表里 200 级的 `level_up_exp` / `cumulative_exp` 都是 NULL；旧文档的 `cumulative_required_exp(level)` 一旦取 200 级就会拿到 NULL 崩掉。新公式只取 `cum(L-1)`，天然避开该行 |
| 4 | **MAD 在 `mad = 0` 时退化** | 若最近 7 天效率完全相同，`robust_sigma = 0`，上下界塌缩成 `baseline`，任何微小波动都被判异常。文档未处理这一分支 |
| 5 | **缺口修正的门限不自洽** | 文档说"缺口 > 3 天才修正"，但 `α = min(1, 2/Δ)`，Δ=4 时 α=0.5、Δ=3 时 α=0.67，实际从 Δ=2 就开始大幅混合，与"3 天"的说法矛盾 |
| 6 | **6.4 置信度公式被截断** | 原文只剩 `confidence = min(1.0, 2 /`，无法实现 |
| 7 | **"经验回档"没有修正规则** | 文档列了异常类型却只字未提怎么修。现实中经验不会减少，出现回退一定是**录入错误**（等级或经验填错），应当作废并提示，而不是做统计修正 |
| 8 | **浮点口径与本项目冲突** | 旧文档用 `REAL` 存经验、输出 `150.2`；本项目看板要求精确整数 + `formatExact` 千分符 |
| 9 | **流程与诉求不匹配** | 旧文档是"每日落库 + 预测 + 趋势状态"的完整系统，本 issue 只要卡片上的一个数 |

### 3.3 关于"漏统计插值"

旧文档把区间增量**均摊到区间的每一天**。实测里存在 16 天缺口（2026-09-25 → 2026-10-11），
均摊会得到"每天都赚 8,193"，但真实情况是这 16 天里可能只有 2～3 天在肝。
均摊出来的每日序列既不能反映真实节奏，又会污染后续任何"基于每日序列"的统计。

**新方案的处理**：不展开成日序列。窗口内直接用**首尾两点求平均**，区间缺口如实反映在分母里，
并在 tooltip 里写明"实际跨度 31.8 天、8 条快照"，让用户自己判断可信度。

## 4. 核心公式

### 4.1 绝对经验（把"等级 + 当前经验"压成一个可比数）

```
absolute(L, exp) =
    exp                                  , L == 1
    cumulative_exp(L - 1) + exp          , L >= 2
```

- `L == 1`：没有 0 级，起点即 0；
- `L >= 2`：`cumulative_exp(L-1)` 是"升入 L 级那一刻"的累计门槛，加上本级已累积的 `exp`；
- `L == 200`（满级）：公式只用 `cum(199)`，不触碰 NULL 行，**可正常计算**；
- `L < 1` 或 `L > 200`，或 `cum(L-1)` 缺失 / 为 NULL → **无法换算**，该快照不参与计算。

实测校验（2026-10-18 快照）：`163 级 / 105,302` → `11,214,610 + 105,302 = 11,319,912`；
首条 `70 级 / 5,157` → `217,617`；全程增量 `11,102,295`。

### 4.2 同日去重

按 `statistics_date` 升序后，**同一天只保留最后一条**。
去重不丢经验：最后一条的绝对经验已经包含当天更早记录的全部增量。
同一天内若出现绝对经验回退，保留最后一条并在 tooltip 记为"当日数据异常"。

### 4.3 窗口效率

```
window = [右端点 - N 天, 右端点]
右端点 = 最新快照时刻（不是"今天"）
起点   = 窗口内最早的一条快照（若窗口内不足 2 条，向前扩大到最近两条快照）

span_days = (右端点 - 起点) / 86400 秒
rate      = (absolute(右端点) - absolute(起点)) / span_days        单位：经验/天
```

**为什么右端点取"最新快照"而不是"今天"**：如果用户 10 天没记录，用今天做右端点会把
10 天的空窗算进分母，效率凭空掉一半——那是"没记录"，不是"没肝"。

**为什么起点允许越出窗口**：窗口内只有 1 条快照时，只能向前找一条凑成区间；
此时 `span_days` 会大于 N，tooltip 里如实显示"近 N 天样本不足，实际区间 …"。

### 4.4 累计日均（tooltip 对照项）

```
cumulative_rate = (最新 absolute - 首条 absolute) / (最新时刻 - 首条时刻)的整天数
```

实测 `11,102,295 / 1,166 ≈ 9,522/天`。它稳定但会被入职时长稀释，只作为对照，不做卡片主值。

## 5. 候选口径对比（同一份数据实测）

| 口径 | 公式 | 2026-10-18 实测 | 特点 |
| --- | --- | --- | --- |
| **近 30 天日均（推荐）** | §4.3，N=30 | **11,336/天**（实际跨度 31.8 天，8 条快照） | 兼顾近期状态与抗噪；一次活动不会把数字带飞 |
| 近 7 天日均 | N=7 | 14,906/天（跨度 7.15 天） | 最灵敏，但一条爆肝记录就能拉高 30% |
| 近 14 天日均 | N=14 | 10,420/天（**实际跨度 22.6 天**） | 该窗口恰好卡在两个快照之间，跨度误差 60%，标签会误导 |
| 近 60 天日均 | N=60 | 10,672/天 | 更平稳，但对"最近开始肝"不敏感 |
| 累计日均 | §4.4 | 9,522/天 | 最稳定，被 3 年前的慢速期稀释 |
| 最近两笔 | 相邻两快照 | 16,133/天（跨度 0.65 天） | 抖动过大（同日两条都能差一倍），不适合做主指标 |

### 5.1 为什么选 30 天

1. 与"按月看成长"的心智模型一致，数值稳定在 1 万上下（实测 10,420～11,336）；
2. 14 天窗口在实测数据上出现了 60% 的跨度误差，说明窗口太短时"样本对齐"不可靠；
3. 7 天太灵敏，用户看到的数会随一次活动大幅跳动，反而不可信。

> 备注：上表 14 天那一行正是"窗口对齐误差"的现场案例，因此 §7 的 tooltip **必须显示真实区间**，
> 不能只写"近 30 天"。

## 6. 计算流程（伪代码）

```text
输入：快照列表 snapshots（按 statistics_date 升序）、等级基准表 cum

1. 逐条换算
   for s in snapshots:
       a = absolute(s.level, s.exp)
       if a is None: 跳过该条，记录 skipped += 1
       else: points.append((s.time, a))

2. 同日去重
   day_last = {}
   for p in points: day_last[p.date] = p          # 后写覆盖
   points = sorted(day_last.values())

3. 样本检查
   if len(points) < 2: 返回 降级("快照不足 2 条")

4. 窗口定位
   end = points[-1]
   start = 最近一个 time <= end.time - 30 天的点
   if start is None or start 是窗口内唯一一点:
       start = points[-2]        # 向前扩一条，标记 样本不足

5. 计算
   span = (end.time - start.time) 的秒数 / 86400
   if span <= 0: 返回 降级("区间跨度不足一天")
   delta = end.absolute - start.absolute
   if delta < 0: 返回 降级("最近快照经验低于起点，疑似录入错误")

6. 输出
   rate = round(delta / span)        # 四舍五入到整数
   附带：起点时间、终点时间、span、样本数、是否扩窗、skipped 数
```

### 6.1 边界一览

| 情况 | 处理 | 卡片显示 |
| --- | --- | --- |
| 无快照 | 降级 | `-`，tooltip「暂无快照」 |
| 仅 1 条快照 | 降级 | `-`，tooltip「至少需要两条快照才能算效率」 |
| 快照等级无法换算（<1 或 >200，或基准缺失） | 跳过该条；若剩余不足 2 条则降级 | `-`，tooltip 说明跳过条数 |
| 同日多条 | 取当日最后一条 | — |
| 窗口内样本不足 | 向前扩一条 | 正常显示，tooltip 标「样本不足」 |
| 跨级（区间内升级多次） | 公式天然支持（绝对值连续） | 正常显示 |
| 绝对经验回退 | 降级 | `-`，tooltip「疑似录入错误」 |
| 区间跨度 < 1 天 | 降级 | `-`，tooltip 说明 |

## 7. 展示设计

### 7.1 卡片

```
指级效率
11,336/天
```

- 用 `formatExact` 加千分符，单位固定 `/天`；
- 降级时为 `-`（与现在一致）；
- tooltip 说明口径，避免"这个数怎么来的"没人知道。

### 7.2 tooltip 文案

```
近 30 天日均｜2026-09-16 18:42 → 2026-10-18 14:01（31.8 天，8 条快照）｜累计日均 9,522/天
```

样本不足时追加一段：

```
…｜样本不足 3 条，已向前扩展窗口
```

降级时：

```
指级效率：至少需要两条可换算的快照（当前 1 条）｜口径：近 30 天绝对经验差 ÷ 实际跨度
```

### 7.3 与 #14 卡片口径的一致性

| 卡片 | 口径 | 格式 |

| 指挥官等级 | 精确值 | `163（105,302/354,350）` |
| 魔方 / 红尖尖 | 大概值（K） | `4.1K` |
