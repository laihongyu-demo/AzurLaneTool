# 活动记录方案与导入报告

- 日期：2026-10-22
- 范围：新增「活动记录」功能、常规录入「支出 · 活动建造」关联活动、`event.csv` 一次性导入
- 数据源：项目根目录 `event.csv`（63 条，2023-08-17 ~ 2026-10-22）
- 目标库：`data/AzurLaneStatisticalOfficeDB.db`

---

## 1. 背景与目标

`event.csv` 是长期手工维护的活动统计表，字段为活动日期、类型、活动、状态、状态备注、
建造次数（CSV 列名为「抽数」）、备注。此前活动数据与资源统计完全割裂：魔方明细里虽然有
383 笔「活动建造」支出（合计 6,181 魔方），但无法知道每笔支出属于哪个活动。

本次交付两件事：

1. 把活动统计变成可增删改查的「活动记录」页签，替换手工 CSV；
2. 让常规录入的「支出 · 活动建造」可以选择所属活动，活动页按活动汇总关联的魔方支出与笔数。

2026-10-22 开启的新活动「飓风与雾霭回廊」作为第一条新数据直接走新流程。

同日追加修复：建造次数不再与关联明细脱节。有明细时按「关联魔方 ÷ 单次消耗 + 建造券次数」
自动计算；活动增加单次消耗（1 / 2 魔方）与建造券入口。今日活动 8 笔 × 20 = 160 魔方、
单耗 2，建造次数由 30 修正为 80。

---

## 2. 已确认的口径

| 决策点 | 结论 | 原因 |
|---|---|---|
| 建造次数口径 | **有明细时 = 关联魔方 ÷ 单次消耗 + 建造券次数**；无明细时用手工 / 历史值 | 建造次数必须与实际消耗对得上；只按魔方计算，券抽单独补充 |
| 单次消耗 | 活动级字段，取值 1 或 2 魔方/次 | 轻型 1 魔方，重型 / 特型 / 多数活动池 2 魔方；同一活动拆卡池时每行各自设置 |
| 建造券 | 活动级「使用建造券」开关 + 券抽次数；券抽不消耗魔方 | 保留券抽入口，但不影响魔方折算 |
| 默认关联 | 「支出 · 活动建造」默认关联当前**进行中**的活动；有多个进行中活动时默认最近一个并在标签上提示确认；没有进行中活动时默认「不关联」 | 正常同一时间只有一个活动在进行；多个并存属于少数情况，交给用户确认 |
| 页面入口 | 新增第 5 个页签「活动记录」 | 63+ 行表格需要筛选与编辑空间，独立页签不挤压资源统计页 |
| 初始数据 | 一次性导入脚本 + 本报告；CSV 的「抽数」列 `0` 按「未统计」导入 | 不把个人历史写进 `sql/` 种子；0 次与未统计在界面上语义不同 |
| 活动粒度 | 一行一个活动 / 卡池 | 同一活动拆成普通池与祈愿池时（如「幽影迷城」与「幽影迷城·特型祈愿」）独立统计 |
| 删除活动 | 只解除明细关联，明细保留 | 活动记录是统计维度，不应级联删除资源明细 |
| 状态 / 类型 | 中文自由文本，状态给建议值（毕业 / 缺 / 进行中） | 避免以后新增状态或活动类型时再做表结构迁移 |

## 3. 数据模型

### 3.1 新增 `event_record`

定义见 `sql/CreateEventRecordTable.sql`：

| 列 | 说明 |
|---|---|
| `event_date` | 活动开始日期 `yyyy-MM-dd`，必填，不得晚于今天 |
| `event_type` | 活动类型，自由文本（如 `大型海域·周年`） |
| `name` | 活动名称；允许为空（历史数据有 1 条空名称） |
| `status` | 状态，自由文本；空串表示未标记 |
| `status_note` | 状态备注（如 `缺吉尚`） |
| `build_cost` | 单次建造消耗的魔方数，1 或 2，默认 2 |
| `use_ticket` | 是否使用过建造券（1 / 0） |
| `ticket_build_count` | 建造券抽次数；仅在有关联明细且 `use_ticket=1` 时计入合计 |
| `build_count` | 建造次数。有明细时展示值由「关联魔方 ÷ 单耗 + 券抽」计算；本列作为无明细时的手工 / 历史回退值 |
| `note` | 备注 |

索引：`idx_event_record_date (event_date)`。

> 旧库升级：`utils/db_schema.py` 的 `_upgradeEventRecordSchema()` 会把旧列 `draws`（抽数）
> 就地重命名为 `build_count`，并补齐 `build_cost`（默认 2）、`use_ticket`（默认 0）、
> `ticket_build_count`（NULL）；数据保留。新库直接按完整字段建表。

### 3.2 `resource_transaction.event_id`

- 新库：`sql/CreateResourceStatisticsTables.sql` 直接建列，并建 `idx_resource_transaction_event`；
- 旧库：`utils/db_schema.py` 的 `_upgradeEventTransactionColumn()` 在执行资源脚本前幂等补列，
  保证随后创建索引时有列可用；
- 一条明细最多关联一个活动；不建外键约束，删除活动由服务层显式解除关联。

## 4. 业务规则

### 4.1 关联写入

只有同时满足以下条件才允许写 `event_id`：

- `resource_type = cube`
- `direction = expense`
- `category = 活动建造`
- `event_id` 对应的活动存在
- `amount` 必须是该活动 `build_cost` 的整数倍（否则无法折算建造次数）

其它类型即使传入 `event_id` 也会被 `ResourceEntryService._validateEventLink()` 拒绝；
金额不是单耗整数倍时直接拦下并提示，避免产生余数。
活动关联是选填项，选「（不关联活动）」仍可正常记账。

默认关联规则（`RegularEntryPanel`）：

- 当前有 1 个「进行中」活动：自动选中该活动；
- 当前有多个「进行中」活动：默认选最近一个，并把活动标签改为「活动（请选择）」提示确认；
- 当前没有「进行中」活动：默认「不关联」，用户仍可手动选择历史活动；
- 用户手动改过选择后，刷新保持其选择，不再自动回默认值。

### 4.2 活动页

- 表格列：日期、类型、活动、状态、单耗、建造次数、关联魔方、笔数、状态备注、备注；
- 建造次数：有明细时按「关联魔方 ÷ 单耗 + 券抽」显示；除不尽时显示 ⚠ 并在 tooltip 给出余数；
  无明细时显示手工 / 历史值；
- 筛选：年份、类型、状态（固定建议值 + 历史自定义值，含「未标记」）、关键词（活动名 / 备注 / 状态备注）；
- 汇总：总数、毕业 / 缺 / 进行中 / 未标记（有自定义状态时追加「其它」）、建造次数合计（按有效值）、关联魔方（有关联的活动数）；
- 新增 / 编辑：`EventRecordDialog` 提供单次消耗（1 / 2 魔方）、建造券开关与券抽次数；
  有明细时建造次数只读并实时预览，无明细时手填；
- 删除：确认框展示关联笔数与魔方数，删除后仅解除关联。

### 4.3 常规录入

`RegularEntryPanel` 在「魔方 + 支出 · 活动建造」时显示「所属活动」行：

- 默认关联当前「进行中」的活动；多个时默认最近一个并提示确认；
- 活动下拉显示单次消耗（如「2魔方/次」），录入金额必须是单耗整数倍；
- 用户改过选择后（包括主动选「不关联」），刷新时保持其选择；
- 其它类型（含红尖尖全部类型）不显示该行，也不会写 `event_id`。

## 5. 一次性导入

### 5.1 脚本

`tools/import_event_csv.py`：

```powershell
python tools/import_event_csv.py            # 预演：解析 + 统计，不写库
python tools/import_event_csv.py --apply    # 正式导入：自动备份，空表才写入
```

规则：

- 日期 `yyyy/M/d` → `yyyy-MM-dd`；
- CSV 的「抽数」列（兼容新列名「建造次数」）导入为 `build_count`；该列 `0` → `NULL`
  （表示「没有统计到具体次数」）；
- 新增的单耗 / 建造券字段使用默认值：`build_cost=2`、`use_ticket=0`、`ticket_build_count=NULL`；
- 空名称 / 空状态 / 空备注原样保留；
- 整批写入同一事务，任一行校验失败整批回滚；
- `event_record` 非空时直接退出，避免重复导入；
- 写库前把数据库复制到 `data/backup/<库名>_event_import_<时间戳>.db`；
- 导入后回读核对数量、日期范围、建造次数合计与已统计条数；
- `event.csv` 仅在导入时使用，导入完成后已从工作区删除，并加入 `.gitignore`，不纳入 Git；
  后续如需重新导入，用 `--csv` 指定新的统计文件。

## 7. 风险与后续

1. **历史明细未回溯关联**：383 笔历史「活动建造」仍是 `event_id = NULL`，活动页只统计新录入。
   若需要按活动回填历史，需要另做按日期区间匹配的工具，并人工确认同日活动拆分。
2. **今日活动状态**：CSV 中 2026-10-22 的状态为空；库内当前为「进行中」，因此默认关联可直接命中。
   其它活动结束后需手工把状态改为毕业 / 缺，避免同时存在多个「进行中」。
3. **建造券与回退值**：券抽必须勾选「使用建造券」并填写次数才计入建造次数；关联魔方除不尽
   单耗时活动页显示 ⚠ 并在 tooltip 给出余数，需要核对明细金额（录入时已拦截非整数倍）。
   有关联明细时以自动折算为准；删除全部关联明细后会回退到最近保存的手工值（今日为 80），
   需要时请手工调整。
4. **单耗需要按活动维护**：旧数据默认单耗 2，只有在关联明细后才会参与折算；1 魔方池需要在
   活动页改为 1，否则建造次数会少算一半。
5. **缺少活动结束日期**：当前无法自动判断「进行中」，状态需手工维护；后续如有需要可加结束日期与自动推断。
6. **明细列表缺失**：关联明细目前只在活动页汇总，逐笔查看仍依赖后续的明细列表（#29）。
7. **空活动名**：2026-08-27 的记录活动名为空，界面显示「（未命名活动）」，可按实际名称补录。
