# 红尖尖固定来源方案（世界巡游 / 贸易许可证）

- 日期：2026-10-24
- 状态：已实现并完成真实库数据迁移（待提交 / 验收）
- 关联：#17（资源录入）、#21（类型字典）、#29（历史列表）、#30（零汇总日补录）、#31（世界巡游）、#32（贸易许可证）、#33（历史月卡盘点）
- 范围：红尖尖固定来源；不改动 `resource_daily` / `resource_transaction` 结构

## 1. 结论

新增两类红尖尖固定来源：

1. **世界巡游**：6 档里程碑，每档 50 红尖尖，每 2 个自然月一期；复用现有任务看板逻辑。
2. **贸易许可证**：每次购买/续约立即记 500 红尖尖，且自动叠加有效期 30 天；每日 1 魔方仍走手动常规录入。

世界巡游的「档期」独立成共享服务，不挂在魔方或红尖尖任一侧；两个任务看板引用同一份档期计算。

历史红尖尖「月卡」77 笔暂不迁移；新数据分别写「世界巡游 / 贸易许可证」，盘点后再决定是否迁移。

## 2. 世界巡游档期独立

### 2.1 现状

`cruisePeriodStart()` / `cruisePeriodEnd()` / `buildPeriodKey("cruise", ...)` 目前位于
`services/cube_task_service.py`，只有魔方看板使用。红尖尖若照抄会形成第二套档期逻辑。

### 2.2 目标结构

| 层 | 文件 | 内容 |
|---|---|---|
| Utils | `utils/task_period.py` | `addMonths`、`weekRange`、`monthRange`、`cruisePeriodStart`、`cruisePeriodEnd`、`buildPeriodKey`、`periodRange` |
| Model | `models/task_period.py` | `TaskPeriodInfo`（period_type / period_key / label / start / end） |
| Service | `services/world_cruise_service.py` | `WorldCruisePeriod`、`WorldCruiseService`：`getPeriod(date)`、`getCurrentPeriod()`、`getPeriodByKey("2026-10")`、`listPeriods()` |
| Service | `services/cube_task_service.py` | 改为引用共享模块；保留同名 re-export，避免现有测试/调用方中断 |
| Service | 红尖尖任务服务 | 同样引用 `WorldCruiseService`，不再自行计算 |

口径保持：

- 每 2 个自然月一期，起点为偶数月 1 日 00:00；
- 当前期（2026-10-24）为 `2026-10-01 ~ 2026-11-30`；
- 期键为起始月 `yyyy-MM`（如 `2026-10`）。

不新建档期表：档期由日期纯计算。若将来游戏实际档期出现例外，再在
`WorldCruiseService` 内集中加覆盖表，不改两个看板。

### 2.3 档期选择

两个看板各自保留现有「记账日期」控件，同时在世界巡游分组内增加「档期」下拉：

- 默认当前期；
- 列出最近若干期（当前期 + 过去期），标签如 `2026-10-01 ~ 2026-11-30`；
- 选择过去期时，把看板记账日期设为该期最后一天；选择当前期时设为今天；
- 日期控件改到另一期时，档期下拉同步到对应期；
- 交易时刻仍按「所选日期 + 当前时分秒」写入，因此金额落在所选档期内，不会被记到今天。

已知取舍：魔方看板的日期控件同时控制日 / 周 / 月任务，选择过去档期会把整个看板切到该日期。
如果后续需要「只切巡游组、不动日/周/月」，再改为组级独立档期参数。

## 4. 贸易许可证

> 「贸易通行证」为笔误，统一使用「贸易许可证」。

### 4.1 数据模型

新表 `trade_license_purchase`：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `purchase_time` | TEXT | `yyyy-MM-dd HH:mm:ss` |
| `start_date` | TEXT | 含当天 |
| `end_date` | TEXT | 含当天 |
| `days` | INTEGER | 默认 30 |
| `amount` | INTEGER | 购买/续约 500；期初登记 0 |
| `transaction_id` | INTEGER | 关联 500 红尖尖明细；期初登记为空 |
| `note` | TEXT | 购买/续约/期初登记 |
| `created_at` | TEXT | |

- 最新记录按 `end_date DESC, id DESC` 取。
- 索引：`idx_trade_license_purchase_end (end_date)`。

### 4.2 状态与续约规则

- 剩余天数：`max(0, (end_date - today).days + 1)`，含今天。
- 未购买：0 天，按钮「购买月卡（+500 红尖尖）」可用。
- 有效且剩余 ≥8：按钮禁用，tooltip 说明。
- 有效且剩余 1~7：按钮可用。
- 已过期：0 天，按钮可用。
- 续约：未过期从当前到期日次日顺延 30 天；已过期/未购买从今天起 30 天。
- 点击后二次确认；确认即写 500 红尖尖 + 购买记录。
- 每日 1 魔方不自动记账，面板只提示：到「魔方任务看板 → 常规录入」手动补记，类型选「贸易许可证」。

### 4.3 首次使用：登记当前到期日

- 无记录时，面板提供「登记已有月卡」：
  - 选择当前到期日；
  - 写 `amount=0`、`transaction_id=NULL` 的记录，不产生 500 红尖尖；
  - `start_date = end_date - 29`，按 30 天卡处理。
- 这样当前在用的月卡能正确显示剩余天数，不会把首次续约误记成 500。

### 4.4 修正与删除（仅最近一条）

| 操作 | 行为 |
|---|---|
| 修正到期日 | 只允许改最近一条的 `end_date`；校验 `end_date >= start_date`；初始记录按 30 天反推 `start_date`，续约记录保留原 `start_date`，重算 `days` |
| 删除最近记录 | 二次确认；若关联 500 红尖尖明细，同事务删除明细、重算该日 `last_record_time`，再删除购买记录；状态回退到上一条 |
| 修改更早记录 | 先删除它之后的记录，再修改；不在本轮做任意行编辑 |

### 4.5 撤销保护

常规录入的「撤销上一笔」当前只排除任务看板明细；贸易许可证的 500 明细必须排除，
否则会删掉红尖尖但保留月卡记录。

- 在 `ResourceRepository.findLatestManualTransaction()` 中排除
  `trade_license_purchase.transaction_id`；
- 表缺失时降级为原查询，避免旧库报错；
- 月卡面板自己的「删除最近记录」负责回滚 500 明细。

### 5.2 历史「月卡」77 笔：先不迁移

迁移文档记录：红尖尖收入「月卡」77 笔 / 13,500。实施前先只读盘点：

```sql
SELECT amount, COUNT(*), MIN(record_time), MAX(record_time)
FROM resource_transaction
WHERE resource_type = 'red_gem'
  AND direction = 'income'
  AND category = '月卡'
GROUP BY amount
ORDER BY amount;
```

```sql
SELECT record_time, amount, note
FROM resource_transaction
WHERE resource_type = 'red_gem' AND direction = 'income' AND category = '月卡'
ORDER BY record_time DESC
LIMIT 20;
```

决策：

- 默认**不自动迁移**，先只读盘点；盘点后按金额规则执行。
- 实际执行（2026-10-24）：`500 → 贸易许可证` 22 笔、`50 → 世界巡游` 55 笔、
  `250 → 世界巡游` 1 笔（5 × 50 聚合）；详见 §9.2 与 `docs/20261024_红尖尖月卡分类盘点.md`。

## 8. 风险

1. 当前期/当前月卡未对齐会造成重复记账；实施前先只读盘点，必要时用仅标记工具。
2. 月卡 500 被常规「撤销上一笔」误删；必须加排除条件。
3. 历史「月卡」若金额不纯，自动迁移会污染统计；本次盘点后 50/250/500 已全部归类。
4. 档期选择移动看板日期会影响魔方日/周/月任务；先按整体日期上下文实现，必要时再做组级隔离。
5. 红尖尖看板采用 4 列网格：世界巡游与常规录入各占 2 列，贸易许可证下一行通栏；实际布局需人工看一次窗口。
6. `cube_task` 表名在扩展后不再精确，仅加注释，不做重命名迁移。
