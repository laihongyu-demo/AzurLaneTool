## 1. 背景与目标

台账迁库后，`resource_daily` / `resource_transaction` / `event_record` 已能支撑收支分析，
但界面只有卡片和表格，没有趋势与结构视图。issue #19 第一阶段明确「只做台账 + 看板卡片」，
图表单独立项；本方案即为该 issue 的落地设计。

用户确认的 5 条数据需求（2026-11-14）：

| # | 需求 | 本期 |
|---|---|---|
| 1 | 魔方 / 红尖尖整体增长趋势 | 做 |
| 2 | 来源 / 去向类目占比（月度 / 总计） | 做 |
| 3 | 军事委托产出概览（重点：月度魔方产出，支持全部 / 近一年） | 做 |
| 4 | 大建详情：各活动池毕业次数趋势、中位数、毕业预测 | 做 |
| 5 | 氪金汇总 | 只记需求，单开 issue |

目标不是「加几个图」，而是让「收支结构是否健康、委托产出是否稳定、下个池要备多少魔方」
这三件事能在一页内读完，并且每个数字都能回到明细核对。

结构性事实（决定图怎么画）：

1. **魔方 2024-10-16 之前的 5,462 / 4,219 只有日合计**，无法拆到类目 → 类目占比只能覆盖明细期；
2. 红尖尖明细从 2025-01-14 起，此前 223 天是 0 收支的「只记结余」日 → 结余曲线可用，占比图只能从 2025-01 起；
3. 结余链有 6 处手填锚点，锚点处曲线会跳变，必须标出来；
4. 主要结构：魔方支出 74.3% 是「活动建造」（6,421/8,641），收入最大项是「军事委托」（3,705，占 31.2%）；
   红尖尖收入 77.9% 来自「礼包 + 充值」（120,794/155,157；字典里的「月卡」当前没有明细）——这批数据正是需求 5 的金额化对象；
5. `event_record` 63 条：**毕业 61 / 缺 2**，毕业池次数合计 5,204，仅 1 条有关联明细（其余为手填值）；
6. 军事委托的 `note` 全为空，**没有委托等级 / 名称维度**，只能做总量、月度、单笔分布。

## 3. 口径设计

### 3.1 整体趋势（需求 1）

- **数据源**：`ResourceService.getBalanceSeries()`（日汇总 + 明细合计 + 锚点重设），与看板卡片同源，不另写结余逻辑。
- 上图：**日结余折线**（可切全部 / 近 12 个月）。锚点日画 ▲ 并标注「手填结余」；同时标注阶段峰谷
  （14 天窗口、按起伏排序）与最大单日涨跌，按归一化距离去重，最多 9 个标签。
- 下图：**月度收入 / 支出柱 + 净额线**。月度值 = 该月每日收入/支出之和（含汇总日），缺失月不画柱（不补 0）。
- 卡片：当前结余、累计收入、累计支出、净增长、记录天数、锚点数。
- 不画趋势回归线：结余受抽卡节奏影响，线性拟合会被误读为「增长率」。

### 3.2 来源 / 去向占比（需求 2）

- **数据源**：`resource_transaction`，按 `substr(record_time,1,7)` 归月；类目名直接用 `category`（改名会同步明细，口径稳定）。
- 左图：**总计横向条形**，按金额降序，全部类目（魔方收入 20 类也放得下），标签带金额 + 占比。
- 右图：**月度堆叠柱**，Top 8 + 「其他」；视图可切「绝对值 / 占比」（占比 = 当月该类 ÷ 当月明细合计）。
- **分母只取明细期**，区块底部固定一行覆盖说明：
  「类目占比仅含明细期 2024-10-16 起｜汇总日 440 天未拆分：收 5,462 / 支 4,219，未计入占比」。
  红尖尖对应 2025-01-14 起、汇总日收支为 0（不产生差额）。
- 停用类目：历史明细仍按原名统计（与规范 §4.2 一致）；字典里不存在的名字归入「其他」并在说明中列出。

### 3.3 军事委托产出（需求 3）

- **数据源**：`category = '军事委托' AND direction = 'income'`，按资源分别统计。类目名收敛到常量
  `MILITARY_COMMISSION_CATEGORY`（设置页可改名，改名后常量需同步，见风险 R5）。
- 范围切换：**全部 / 近一年**。近一年 = 以 `time_source.today()` 所在自然月为末月往前推 12 个自然月
  （2026-11 时即 2025-12 ~ 2026-11）。
- 上图：**月度产出柱**（全部范围叠加 12 个月移动平均；近一年范围不画均线，避免半截均线误导）。
- 下图：**单笔金额分布**（按金额聚合的条形）。魔方集中在 1–5，红尖尖集中在 10–40，两资源分别标度。
- 卡片：累计产出、笔数、单笔均值、有记录日均值（分母 = 该类别有记录的天数，不是自然日）、最高单笔。
- 魔方基准数据：全部 1,814 笔 / 3,705；近一年（2025-12 ~ 2026-11）1,103 笔 / 2,032。

### 3.4 大建详情（需求 4）

- **数据源**：`EventRecordService.listRecords()` 的 `EventRecordView.build_count`（有明细时 = 关联魔方 ÷ 单耗 + 券抽；
  无明细时用手填值），**只保留 `status == EVENT_STATUS_GRADUATED`（毕业）**，其余池不进图表与统计。
- 样本：61 个毕业池（2023-09-14 ~ 2026-10-22），次数合计 5,204。
- 图 A（1×2）：
  - 左：**时间序列散点/柱 + 近 10 池滚动中位数**。不拟合回归线：年度中位数 90 / 69 / 80 / 80（N=4/21/21/15），
    趋势基本平，滚动中位数只描述「近期贵不贵」，不宣称趋势方向。
  - 右：**分布直方图**（0–240，步长 20）+ P25 / P50 / P90 竖线。
- 图 B（1×2）：
  - 左：**按类型中位数条形**，标注样本量：祈愿 35（N=6）/ 复刻 68（N=14）/ 首次活动 89（N=41）。
    小样本必须标 N，否则「祈愿更便宜」会被过度采信。
  - 右：**经验生存曲线** `P(T > n)`，用于毕业预测（见 3.5）。
- 卡片：毕业池数、次数合计、中位数、均值、P75、P90。

### 3.5 毕业预测（需求 4 的延伸）

把历史毕业次数 `T` 当作经验分布，做两件只读的事，**不做概率承诺**：

1. **新池预算**：按所选样本范围取 `Q50 / Q75 / Q90`，乘单耗得到魔方预算。
   全部样本、单耗 2 时为 79 次 → 158 魔方 / 100 次 → 200 / 170 次 → 340。
2. **当前池对照**：输入已抽次数 n（默认 0；若存在「进行中」池可一键带入其派生次数）：
   - 分位排名 `r = ( #{T < n} + 0.5·#{T = n} ) / N`，展示「超过 r 比例的历史池」；
   - 剩余样本 `S = { T − n | T > n }`，取其中位数与 P75 作为「还需次数」，乘单耗得「还需魔方」；
   - `S` 为空（n ≥ 220）时提示「已超过历史最高，样本无法估计」。
- 分位数用**线性插值**（与 numpy 默认一致），实现为一个纯函数并单测。
- 样本范围可选：全部（61）/ 排除祈愿（55）/ 仅复刻（14）/ 仅祈愿（6），界面始终显示 N 与中位数。
- 边界与免责：2 条「缺」没有次数、属右删失，未计入；池内限定舰娘数量不同、单耗 1 仅 2 条；
  若游戏存在保底机制，经验分布未建模。以上写进图下说明，不用「预测概率」措辞。

### 3.6 通用口径

- 未记录 ≠ 0：月度缺口不画柱（NaN），不补零；日环比类逻辑不在本页。
- 缺表 / 缺列：沿用 `isMissingTableError()` / `isMissingColumnError()`，降级为空结果 + 页面提示，不抛到界面。
- 时间：只用 `utils.time_source`；本页唯一的「今天」依赖是「近一年」区间与跨天刷新。
- 数值展示：概览用 `formatValue()`，核对数字（金额、次数、分位）用 `formatExact()`，同一处不混用。

### 5.3 Repository 新增查询（3 个）

实现时比方案多出 1 条：单笔分布只能给出「金额 → 笔数」，笔数合计与最高单笔可以在内存里算，
但「有记录的天数」在按类别与月份过滤后无法从月度聚合里还原，因此单独加了一条只读计数。

```sql
-- 1) 月度 × 类目 金额与笔数（趋势类目、军事委托月度共用）
SELECT substr(record_time, 1, 7) AS month, category, COUNT(*) AS cnt, SUM(amount) AS total
FROM resource_transaction
WHERE resource_type = ? AND direction = ?
GROUP BY month, category

-- 2) 单笔金额分布（军事委托产出概览）
SELECT amount, COUNT(*) AS cnt
FROM resource_transaction
WHERE resource_type = ? AND direction = 'income' AND category = ?
GROUP BY amount

-- 3) 该类目有记录的天数（日均分母；可带月份区间）
SELECT COUNT(DISTINCT substr(record_time, 1, 10)) AS days
FROM resource_transaction
WHERE resource_type = ? AND direction = 'income' AND category = ?
  AND substr(record_time, 1, 7) BETWEEN ? AND ?
```

覆盖区间、汇总日金额、月度收支等均由服务用**已有**查询（`findAllDaily` + `findTransactionTotals`）在内存聚合；
事件侧完全复用 `EventRecordService`，不写新 SQL。

### 6.2 交互与空状态

- 资源、方向、范围、月度视图切换：只重算对应区块，不重建整页。
- **数据标签**：折线只标突出点（最新 / 最高 / 最低 / 手填结余），按归一化距离去重、贴边标签向内收；
  柱状图与散点不常驻标签，改为**悬停读数**（QToolTip），避免密集重叠。
  悬停覆盖：结余（日期 / 结余 / 当日收支）、月度收支、类目（总计、月份 × 类目）、
  委托（月度产出 / 单笔分布）、大建（活动详情 / 分布区间 / 类型统计 / 生存概率）。
- 空数据：画布居中显示「暂无数据」+ 一行原因（无记录 / 旧库缺表），不抛异常。
- 大建详情页脚固定一行：样本 N、只含毕业池、单耗 1 仅 2 条、缺 2 条未计入。
