## 四、数据库改动：等级名统一为 ASCII `II`

- **改动**：`codex_group.ship_level` 中 60 行 `认知觉醒Ⅱ` → `认知觉醒II`
- **方式**：与上一次日期归一化相同的「触发器感知」处理——单事务内 `DROP TRIGGER` → `UPDATE` → 原样 `CREATE TRIGGER`，
  避免 `codex_group` 上的 `update_codex_group_modtime` 触发器把这 60 行的 `date_edit` 改写成运行时间
- **写库前快照**：`data/backup/AzurLaneStatisticalOfficeDB_20261012_pre_level_ii.db`

**验证（6/6 通过）**

| 检查项 | 结果 |
| --- | --- |
| 罗马数字 `Ⅱ` 残留 | 0 行（ASCII `II` 60 行） |
| `date_edit` 变化 | **0 行**（触发器副作用未发生） |
| 其它字段变化 | 0 行 |
| 触发器 | 仍在（1 个） |
| 科技总量：迁移前（罗马映射） vs 迁移后（ASCII 映射） | 完全一致 |
| 应用层读数 | 与 SQL 结果一致 |
| PRY 与 SSR、DR 与 UR 的 5 个阶段消耗 | 完全一致 |

> 反向验证：若**只改代码不改数据**（代码用 ASCII、数据仍是罗马数字），60 行会落入 `ELSE 0` 被当作未觉醒 → 「至五阶」总量会虚高到 `7,161,800`（虚增 1,568,600）。这正是本次必须同时迁移数据的原因。
