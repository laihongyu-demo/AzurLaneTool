## 0. 结论摘要

| 项 | 结论 |
| --- | --- |
| 需求 1 触发 | **到期复跑**（≥90 天 或 新增 ≥100 条有效快照）**+ 事件复核**（fast/slow 偏离 ≥25% 持续 ≥5 天，或 ≥50% 持续 ≥3 天） |
| 需求 1 动作 | **只提醒 + 一键回测 + 归档报告**；不改主值、不改常量、不自动调参 |
| 需求 1 依据 | 历史 8 次事件中，事件后 30 天只有 25%～33% 延续（基线 36%）：事件是「值得复核」的信号，不是「该换口径」的证据 |
| 需求 2 口径 | `remaining(T) = cum(T-1) − (cum(L-1) + exp)`；≤90 天用 30 天口径，>90 天同时给 90 天长期参考 |
| 需求 2 展示 | 「指级经验」窗口新增「升级预测」分组：自选目标 + 里程碑表（165～200），显示剩余经验 / 天数 / 日期 / 近期情景 |
| 库结构 | **不变**；回测运行记录存 `data/` 本地 JSON（与 `data/user.json` 同类） |
| 状态 | **已实现（2026-10-26，P0～P3）**，实施记录见 §11 |

一句话：**回测负责“发现该复核了”，人负责“改不改”；目标等级预测负责“到 X 级还要多久”，但必须把“按现在节奏”和“长期误差”说清楚。**

## 1. 需求拆解

### 1.1 需求 1：定期回测 + 大幅波动时校准

| 子项 | 用户表述 | 本方案的落点 |
| --- | --- | --- |
| 1a | 定期回测 | 到期判定（时间 / 样本增量）+ 设置页「立即回测」+ 报告归档 |
| 1b | 经验获取大幅上升/下降时校准 | 事件检测器（方向 + 幅度 + 持续 + 冷却）+ 「待复核」标记 |
| 1c | 校准 | 报告给出候选表与推荐值；**应用需改代码常量 + 报告**，运行时不自动改 |
| 1d | 采样节奏 | 维持「每天 ≥1 条」；多次采样对 30 天端点无增益，只对 fast/趋势有用（§2.1） |

验收（可观察）：

1. 设置页能看到「上次回测时间 / 距今天数 / 距上次新增快照数 / 待复核事件数」；
2. 到期或事件命中时，有明确提示且能一键运行回测，运行完写入本地记录并生成报告；
3. 回测结果与 `tools/backtest_exp_efficiency.py` 同源同数；
4. 运行前后：主值、常量、数据库均不变（可用测试断言）。

### 1.2 需求 2：自选目标等级预测升级时间

| 子项 | 用户表述 | 本方案落点 |
| --- | --- | --- |
| 2a | 自选等级 | 目标等级输入（164～200，默认当前+1） |
| 2b | 升级时间 | 剩余经验 ÷ 速率 → 天数 + 预计日期 |
| 2c | 分别需要多久 | 里程碑表：165/170/175/180/185/190/195/200 一次列出 |

验收：

1. 目标 = 当前+1 时，剩余经验与服务层「升级还需」完全一致；
2. 目标 = 200 时用 `cum(199)`，不触碰 200 级 NULL 行；
3. 目标 ≤ 当前等级、基准缺失、速率缺失都有明确文案，不崩界面；
4. 不输出「A～B 天」这类伪区间。

### 1.3 明确不做

- 运行时自动改主值 / 自动套用回测推荐阈值（#23 §7.6 的结论继续有效）；
- 事件发生时立刻切换口径（数据不支持：§2.4）；
- 目标等级预测输出置信区间（覆盖率不足，只会制造伪精度）；
- 新增数据库表、逐日落库、异步框架级改造；
- 卡片新增角标（沿用 #23「只放 tooltip」的决策）。

### 2.4 速率口径与前瞻误差（walk-forward，同 #23 工具）

| 估计窗口 | 30d 前瞻 MAPE | 90d 前瞻 MAPE | 180d 前瞻 MAPE | 365d 前瞻 MAPE |
| --- | ---: | ---: | ---: | ---: |
| 30 天（主值） | 21.7% | 22.0% | 20.2% | 19.2% |
| **90 天** | **18.3%** | **16.2%** | **15.4%** | **16.0%** |
| 365 天 | 21.3% | 18.3% | 18.4% | 18.1% |

读法：

- 目标越远，**90 天窗口在所有前瞻期都优于 30 天窗口**；
- 但 90 天窗口更慢（阶跃响应 38 天 vs 25 天），所以**主值仍用 30 天**，只在“目标等级预测”里把 90 天作为长期参考；
- 误差量级 ~15%～22%：到 200 级的 ±20% 就是 ±350 天（约一年），文案必须写“按当前节奏估算”，不能给精确日期承诺。

### 2.5 事件持续性（决定“事件后要不要动口径”）

以 fast/slow 偏离 ±25% 持续 ≥5 个自然日为“事件”，历史 3.2 年共 **8 次**（4 次加速、4 次放缓）；事件结束后未来 30 天实际速率相对当时 30 天值的比值：

| 事件方向 | 事件数 | 未来 30 天中位数 | 落在 ±10% 的比例 |
| --- | ---: | ---: | ---: |
| 加速（≥1.25） | 4 | 0.65 | 33% |
| 放缓（≤0.75） | 4 | 0.88 | 25% |
| 全部 origin 基线 | 423 | 1.01 | 36% |

结论：**事件后的“延续率”并不高于随机时点**，说明大多数突变是短期的（活动、爆肝、长草），把它当成“新常态”去改口径会经常改错。所以事件只能当**复核触发器**：

1. 提醒用户“最近节奏偏离 30 天基线 ≥25%，建议复跑回测确认常量是否仍适用”；
2. 回测报告里附上“本事件期间：候选口径/阈值在该段的误差”；
3. 是否调整由人决定，调整必须改常量 + 更新报告。

## 3. 需求 1 方案：定期回测 + 事件复核

### 3.1 触发条件

三类触发，取并集，任一命中即标记“待回测”：

| 触发 | 规则 | 说明 |
| --- | --- | --- |
| 到期（时间） | `today − last_run_at ≥ 90 天` | 与 #23 §7.5「每季度一次」一致 |
| 到期（样本） | `有效快照数 − points_at_run ≥ 100` | 与 #23 §7.5「或 +100 条」一致 |
| 事件复核 | §3.2 检测到未处理事件 | 事件入队，直到被标记“已复核” |

冷却：同一个方向的事件 30 天内只记一次；一次回测最多把当时所有待复核事件标为“已复核”。

### 3.2 事件检测器

输入：`CommanderService.collectAbsolutePoints()` 的日级点（与卡片同源，不新增 SQL）。

对每个 origin 计算（全部复用现有静态方法）：

```
slow   = 30 天端点
block  = 连续块（gap>7 重置，cap 14）
fast   = 端点差 / 跨度（≥2 条且跨度 ≥1 天）
ratio  = fast / slow
```

候选条件（与卡片趋势一致）：`block ≥3 条`、`跨度 ≥3 天`、`slow > 0`。

| 事件 | 条件 | 历史触发次数（3.2 年） |
| --- | --- | ---: |
| 加速事件 | `ratio ≥ 1.25` 连续 ≥5 个自然日 | 4 |
| 放缓事件 | `ratio ≤ 0.75` 连续 ≥5 个自然日 | 4 |
| 强加速 | `ratio ≥ 1.50` 连续 ≥3 个自然日 | 1 |
| 强放缓 | `ratio ≤ 0.50` 连续 ≥3 个自然日 | 1 |

阈值来源：`1.25/0.75` 沿用 #23 §2.8 的校准；「持续 ≥5 天」是新增的防抖（单日尖峰不算事件）。历史频率 ≈ 2.5 次/年，不会天天弹提示。

事件记录字段：`direction`、`start_date`、`end_date`、`peak_ratio`、`slow_at_start`、`slow_at_end`、`sample_count`、`handled_at`。

### 3.5 “校准”的动作边界

| 动作 | 允许 | 说明 |
| --- | --- | --- |

### 3.6 采样建议（写入设置页提示，不强制）

- 每天至少 1 条：保证 30 天窗口有 ~30 个日点；
- 一天多条时，间隔 ≥6 小时：对 fast 连续块与趋势判定更有用；
- 连续 7 天以上不记录：`fast` 会按缺口重置（符合设计），tooltip 会提示“近期样本不足/数据已 N 天未更新”；
- 记录时间尽量贴近“上线/下线”时刻，避免跨度被随机时点放大。

## 4. 需求 2 方案：目标等级预测

### 4.1 口径与公式

沿用绝对经验：

```
absolute(L, exp) = (L == 1) ? exp : cum(L-1) + exp
remaining(T)     = cum(T-1) - absolute(L, exp)        # T ≥ L+1
```

- `T = L+1` 时，`remaining = level_up_exp - exp`，与卡片角标的“升级还需”一致；
- `T = 200` 用 `cum(199)`，不读 200 级 NULL 行；
- 目标 ≤ 当前等级：`remaining = 0`，显示“已在该等级/已超过”。

### 4.2 速率口径

| 目标距离 | 主展示 | 附加 |
| --- | --- | --- |
| ≤90 天 | 30 天日均（与卡片同源） | 趋势明确时追加「若维持近期节奏 X 天」 |
| >90 天 | 30 天日均 | **同时给 90 天长期口径**，并标注“长期估算，误差约 ±20%” |

理由：§2.4 显示 90 天窗口在 90/180/365 天前瞻都更准，且到 200 级这种 4～5 年的目标，用 30 天窗口等于用最近一个月的状态外推 5 年。

### 4.3 接口

`ExpEfficiency` 追加一个只读字段（不参与主值、不改变 tooltip）：

```python
long_rate_per_day: Optional[int] = None   # 90 天端点日均，供目标等级预测
```

新增 dataclass 与方法：

```python
@dataclass
class TargetLevelProjection:
    target_level: int
    current_level: int
    current_absolute_exp: int
    target_absolute_exp: Optional[int]   # cum(T-1)
    remaining_exp: Optional[int]
    days_slow: Optional[float]           # 30 天口径
    days_long: Optional[float]           # 90 天口径
    days_fast: Optional[float]           # 近期情景（仅加速/放缓时）
    estimated_date: Optional[str]        # today + round(days_slow)
    degraded_reason: Optional[str]

class CommanderService:
    def getTargetLevelProjection(self, target_level: int) -> TargetLevelProjection: ...
    def listTargetLevelProjections(self, targets: Sequence[int]) -> List[TargetLevelProjection]: ...
```

边界文案：

| 情况 | `remaining_exp` | 卡片/表格文案 |
| --- | --- | --- |
| 目标 = 当前等级 | 0 | `已在该等级` |
| 目标 < 当前等级 | 0 | `目标低于当前等级` |
| 目标 = 200 且已满级 | 0 | `已满级` |
| 目标等级基准缺失 | None | `缺少该等级的基准数据` |
| 速率缺失（不足两条快照） | 有值 | `指级效率数据不足，暂无法估算天数` |
| 目标 >200 或 <1 | None | 控件层限制 + 服务层 `ValidationError` |

### 4.5 文案与精度

| 项 | 约定 |
| --- | --- |
| 天数 | 1 位小数 + `天`；`formatExact` 只用于经验 |
| 日期 | `yyyy-MM-dd`；由 `time_source.today() + timedelta(days=round(days))` 得出 |
| 长期提示 | 目标 >90 天时附 `长期估算，误差约 ±20%` |
| 近期情景 | 仅 `trend ∈ {accelerating, decelerating}` 且 `fast > 0` 时追加 `若维持近期节奏 X 天` |
| 不写区间 | 不输出「A～B 天」「最快/最慢」，理由同 #23 §6.3 |
| 满级 | 目标 200 且当前 200：`已满级`，不显示日期 |

### 4.6 性能

- 同一份 points 上多算一个 90 天端点：O(n)，与现有扫描同量级；
- 里程碑 8 行只是 8 次查基准表（按等级缓存）+ 乘除，无 SQL 增量；
- 缓存沿用 `getExpEfficiency()`，按天失效；目标等级切换不触发重新扫描。

## 9. 风险与回退

| 风险 | 缓解 |
| --- | --- |
| 同步回测卡 UI 1 秒 | 等待光标 + 按钮禁用；数据量增长到 >2000 点时再评估线程 |
| 事件误报（历史延续率≈基线） | 只提示复核、不自动改；冷却 30 天；文案写“建议复核”而非“已变化” |
| 目标等级显示伪精度 | 只给 1 位小数 + 长期 ±20% 提示 + 不写区间 |
| JSON 状态损坏 | 容错读 + 原子写；损坏即视为“从未回测” |
| 回测结果与 CLI 不一致 | 工具改为调用同一 service；`--selftest` 与单测共用数据 |
| 报告误入库 | `data/backtest/` 与状态 JSON 加入 `.gitignore`；正式报告仍手工整理到 `docs/` |

回退：需求 1 全部是新增文件与设置页区块，删掉即恢复；需求 2 只新增字段与方法，`rate_per_day` 与卡片不变。

## 10. 决策记录（2026-10-26 已确认）

| # | 问题 | 采用 | 依据 |
| --- | --- | --- | --- |
| Q1 | 回测运行方式 | **手动一键 + 到期提示**，不启动自动跑 | 避免引入线程与启动变慢；1 秒同步可接受 |
| Q2 | “校准”是否可一键应用 | **不应用**，只出报告与建议 | 事件延续率≈基线（§2.5），自动换口径会经常改错 |
| Q3 | 目标等级速率口径 | **30 天主值 + 90 天长期参考**，>90 天标长期估算 | 90 天窗口在 90/180/365 天前瞻 MAPE 更低（§2.4） |
| Q4 | 运行记录存储 | `data/` JSON（不改库结构） | 与 `data/user.json` 同模式，便于人工查看 |
| Q5 | 事件阈值 | ±25% / ≥5 天；强事件 ±50% / ≥3 天 | 历史 3.2 年触发 8 次（≈2.5 次/年），不扰民；上线后由回测复核 |
