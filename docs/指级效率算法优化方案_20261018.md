## 1. 背景与目标

### 1.1 v1 现状

v1（#16，`daea194`）已实现：

```
absolute(1)   = 当前经验
absolute(L)   = cumulative_exp(L-1) + 当前经验        （L ≥ 2，满级 200 也走这条）
窗口          = [最新快照 - 30 天, 最新快照]，起点取边界之前最近一条
rate          = (absolute(末) - absolute(起)) / 实际跨度
```

卡片显示 `11,374/天`，tooltip 显示区间、跨度、样本数与累计日均；无快照 / 仅一条 / 回退 / 缺表时降级为 `-`。18 个算法用例 + 2 个面板用例已覆盖。

### 1.2 三个遗留问题

| # | 问题 | 实测证据 |
| --- | --- | --- |
| 1 | **滞后**：30 天窗口平均不是当前节奏 | 近 30 天 `11,374/天`；近 7 天 `15,023/天`，高 32% |
| 2 | **缺口不可见**：窗口里的长缺口没有提示 | 09-25 → 10-11 缺口 **15.65 天**，期间仅 `8,377/天`；tooltip 只写总跨度 |
| 3 | **不可校准 / 不可信**：阈值写死、异常与过期无提示 | 无回测工具；异常快照、数据 N 天未更新都不会告诉用户 |

### 1.3 目标

1. **及时**：用户能在卡片上“立刻看到”近期节奏变化，而不是等 30 天窗口自然滚过去；
2. **可信**：数字为什么偏低/偏高，缺口、异常、数据截止时间要能解释；
3. **可复现**：窗口、gap、阈值由历史回测校准，报告可复查，不拍脑袋；
4. **低风险**：不改主值语义、不改库结构、不引入异步/重型模型。

### 1.4 明确不做

| 不做 | 原因 |
| --- | --- |
| 把主值换成 7 天 / 自适应主值 | 回测显示 30 天前瞻 MAPE 基本不变（21.6%～21.8% vs 21.7%），抖动 +21%～62%（§2.6） |
| Kalman / BOCPD / λ 衰减预测 | 状态空间调参成本高；本次数据不支持“预测未来效率”的收益 |
| MAD / 分位裁剪异常 | 日增本身长尾（P25 5,079 / P75 13,137），裁剪会把真实活动日抹平 |
| 逐日 `daily_exp_efficiency` 落库 | 486 条日点在内存里算是毫秒级，卡片不需要日表 |
| 周内季节性修正 | 30 天平均已平滑；没有“今日建议”类消费方 |
| 卡片角标 | 本期只放 tooltip；角标涉及“红涨绿跌”语义，单独再议 |
| 运行时自动调参 | 样本仅 400+ origin、regime 会变；自动调参会悄悄换口径 |

### 2.2 关键事实：中间快照不增加“窗口平均”的信息

累计经验 `A(t)` 是**精确值**（录入正确时），不是带噪声的观测。窗口 `[s, e]` 的平均效率就是：

```
R = (A(e) - A(s)) / (e - s)
```

中间快照 `A(t_i)` 不进入这个式子；它只能帮助判断“节奏什么时候变了”，不能改变窗口平均本身。对 `A(t)` 做 OLS / Theil-Sen / Kalman，得到的是**另一个泛函**（斜率、加权平均、末态速率），不是“30 天平均”。

所以：

- 想优化“30 天平均”的精度 → 没有空间，端点差已经是充分统计量；
- 想优化“当前节奏”/“及时性” → 必须换目标，用短窗或变化检测；
- 想优化“可信度” → 做缺口、异常、样本量、新鲜度。

这三件事不能用一个数字同时解决。

### 2.3 回测口径

- 在每个快照时点 `t_i`，只用 `≤ t_i` 的数据估计；
- 目标值 = `t_i` 之后首个 `≥ H` 天的快照的实际平均；允许 `+3` 天容差，避免把 17 天的跨度硬当成 7 天；
- 样本 410～466 个 origin（不同 horizon 略有差异）；
- 「抖动」= 相邻两次录入估值变化的平均绝对值（经验/天）；
- 「阶跃响应」= 合成“前 60 天 5,000/天、之后 15,000/天、每日快照”，估值进入 ±10% 所需天数。

> 这是离线分析口径，不是线上实时指标；样本不大，数字看**相对关系**，不要当绝对精度。

### 2.4 候选口径对比

| 口径 | 7d 前瞻 MAPE | 30d 前瞻 MAPE | 抖动 | 阶跃响应（到 10%） |
| --- | ---: | ---: | ---: | ---: |
| 30 天端点（现） | 29.7% | 21.7% | **265** | 26 天 |
| 7 天端点 | 30.4% | 27.2% | 848 | **6 天** |
| 长窗指数加权回归 | 29.1% | 18.5% | **79** | 79 天 |
| 分段 EWMA（半衰期 30 天） | 27.7% | 17.6% | 146 | 70 天 |

**读法**：平滑口径（长窗回归 / 分段 EWMA）更准、更稳，但阶跃后要 70～79 天才收敛；短窗 6 天就响应，但 MAPE 最差、抖动是 30 天口径的 3 倍。**没有单一口径同时满足准 / 稳 / 及时**。

### 2.5 窗口长度敏感性

| 慢窗口 | 7d 前瞻 MAPE | 30d 前瞻 MAPE | 说明 |
| ---: | ---: | ---: | --- |
| 21 天 | 29.4% | 22.6% | 更灵敏，但更抖 |
| **30 天（现）** | 29.7% | 21.7% | 当前选择 |
| 45 天 | 30.3% | 20.7% | 略准，标签不直观 |
| 60 天 | 29.4% | 20.1% | 更准，更慢 |
| 90 天 | 29.0% | 18.3% | 最准，最慢 |

长窗口确实更准，但“近 90 天日均”已经不是用户心智里的“最近效率”。本期保留 30 天，是**产品取舍**，不是统计最优；如果以后主值只负责“稳定基线”，可以再评估 45/60 天（§14 Q1 已关闭，仍可回访）。

### 2.6 为什么不做“自适应主值”

我试过：检测到 `fast/slow` 偏离 ±25% 时，把主值按 α 混向 fast。

| α | 7d MAPE | 14d MAPE | 30d MAPE | 抖动 |
| ---: | ---: | ---: | ---: | ---: |
| 0（现） | 29.7% | 25.9% | 21.7% | 265 |
| 0.3 | 29.0% | 25.3% | 21.6% | 322 |
| 0.5 | 28.8% | 25.0% | 21.7% | 374 |
| 0.7 | 28.8% | 25.0% | 21.8% | 429 |

7 天略好（-0.9pp），30 天基本不赚（21.6%～21.8% vs 21.7%），抖动 +21%～62%。**结论：不值得为这点收益让主值跳变。** 主值保持 30 天，fast 只做信号。

### 2.7 趋势信号的前瞻检验

把 `fast/slow ≥ 1.25` 记为“加速”、`≤ 0.75` 记为“放缓”，要求 fast ≥3 条且跨度 ≥3 天；看未来 14 天实际效率：

| 信号 | 占比 | 未来 14 天实际均值 | 当时 30 天值 | 实际高于 30 天值 |
| --- | ---: | ---: | ---: | ---: |
| 加速（≥1.25） | 9% | 11,455 | 9,543 | **67%** |
| 平稳 | 80% | 8,889 | 8,979 | 52% |
| 放缓（≤0.75） | 7% | 7,937 | 9,586 | **23%** |

基线是 `P(实际 > 30 天值) = 51.2%`；放缓看的是反向口径 `P(实际 < 30 天值) = 48.8%`。加速组 +15pp，放缓组 +28pp（77% 低于 30 天值），**方向上有信息**。余下 3% 是 fast 样本不足、不判趋势的 origin（四舍五入后合计 99%）。

但 fast 本身是**有偏的**：

- 加速组 fast 均值 13,075，未来 14 天实际 11,455 → **高估 14%**；
- 拉到 30 天窗口，实际 9,736，fast 12,998 → **高估 33%**。

所以 fast 只能做“方向 / 情景”，不能当“点估计”，更不能线性外推到 30 天。

### 2.8 阈值校准

| 阈值 | 信号频率 | 命中率 | 相对基线 lift |
| --- | ---: | ---: | ---: |
| 加速 ≥1.25 | 10% | 67% | +15pp |
| 加速 ≥1.30 | 7% | 63% | +12pp |
| 放缓 ≤0.75 | 7% | 77% | +28pp |
| 放缓 ≤0.80 | 12% | 61% | +12pp |

`1.25 / 0.75` 是“相对 30 天值偏离 ±25%”，文案好写，频率 7%～10%，精度也够。样本不大，阈值作为**初始值**，由回测工具每季度复核。

## 3. 方案总览

| 层 | 内容 | 是否改主值 | 风险 |
| --- | --- | --- | --- |
| L0 数据质量 | 快照校验、异常隔离、缺口、新鲜度 | 否 | 低 |
| L1 双速指标 | slow（30 天）+ fast（连续块）+ trend | 否 | 低 |
| L2 展示 | tooltip 三层 + 升级情景 | 否 | 低 |
| L3 历史校准 | 离线回测工具 + 报告 + 季度复核 | 否 | 低（离线） |

### 3.1 总原则

1. **估计用慢，信号用快**：主值 / 升级天数用 slow；fast 只回答“最近节奏变了没有”。
2. **不混成一个数**：fast 有偏且会均值回归，混进主值会同时损失稳定性和准确性（§2.6）。
3. **历史只用于离线校准**：运行时只做确定性规则（gap reset、阈值判断），不学习、不自适应。
4. **能解释**：每个数字都能在 tooltip 里找到起点、终点、样本数、缺口、截止时间。
5. **不改库**：所有信息都能从现有 `commander_info` + `commander_level_exp` 现算。

## 4. L0 数据质量

### 4.1 快照有效性

逐条校验，先分类再计算：

| 分类 | 规则 | 去向 |
| --- | --- | --- |
| 无法换算 | `level` 不在 1～200，或 `cum(L-1)` 缺失 / NULL | `skipped`，与 v1 语义一致 |
| 可换算但异常 | `exp < 0`；`exp > level_up_exp`（满级 200 除外）；`absolute` 小于上一条有效值 | `invalid_count`，不参与计算 |

> 注意：`exp > level_up_exp` 在写入时已由 `_validateSnapshot()` 拦截；这里再校验一次，是为了覆盖旧库、迁移数据、外部写库。

### 4.2 异常隔离与回退

- 先校验，再按天去重；同一天只保留**最后一条有效**快照；
- 如果最新一条无效，窗口右端点回退到上一条有效快照，tooltip 标注“最新 N 条异常，已按上一条计算”；
- 如果有效点不足 2 条，按 v1 的降级路径返回 `-`。

### 4.3 缺口与新鲜度

| 字段 | 定义 | 用途 |
| --- | --- | --- |
| `gap_days` | 慢窗口 `[start, end]` 内相邻有效快照的最大间隔（天） | ≥7 天时 tooltip 提示“窗口内最大缺口 X 天” |
| `stale_days` | `now - end` 的整天数（向下取整） | ≥7 天时 tooltip 提示“数据已 N 天未更新，效率可能失真” |

`gap_days` 只统计窗口内的缺口；窗口起点之前的不算。`stale_days` 以“最新有效快照”为基准，回退时也按回退后的端点算。

### 4.4 降级

沿用 v1，并补充原因：

| 情况 | 卡片 | tooltip |
| --- | --- | --- |
| 无快照 | `-` | “暂无快照，请先录入指挥官等级” |
| 仅 1 条有效 | `-` | “至少需要两条可换算的快照（当前 1 条）” |
| 最新异常且无上一条 | `-` | “最新快照异常，且没有可回退的有效快照” |
| 绝对经验回退 | `-` | v1 文案 + 异常条数 |
| 缺表 / 空库 | `-` | v1 文案，不让整块看板报错 |

## 5. L1 双速指标

### 5.1 slow（主值，不变）

```
end        = 最新有效快照
cutoff     = end - 30 天
start      = cutoff 之前最近的一条有效快照
             （若全部历史都在窗口内，用最早一条）
slow       = (A(end) - A(start)) / (end - start)    单位：经验/天
```

与 v1 完全一致；`rate_per_day` 仍表示 slow，所有旧测试与卡片文本不变。

### 5.2 fast（近期节奏）

```
block = 从 end 往回走，遇到相邻间隔 > 7 天的缺口就停
        且只保留 end - 14 天以内的点
fast  = (A(block 末) - A(block 首)) / (block 末 - block 首)
```

约束：

- `block` 至少 2 条、跨度 ≥1 天；否则 `fast = None`（“近期样本不足”）；
- **严格 cap**：不为了凑 2 条而回退到 14 天以外的点；宁可 `None`，也不要用 20 天前的点冒充“近期”；
- 用端点平均，不用段速率平均：段速率会被“记录频率”加权，用户越活跃记录越多，会高估真实节奏；端点差 ÷ 时间不会被记录频率带偏。

### 5.3 trend（趋势）

```
ratio = fast / slow
```

| 条件 | trend | 文案 |
| --- | --- | --- |
| `fast` 为空 | `None` | “近期样本不足” |
| `fast` 有值但 <3 条或跨度 <3 天 | `None` | “样本较少，暂不判断趋势” |
| `ratio ≥ 1.25` | `accelerating` | “加速 +32%” |
| `ratio ≤ 0.75` | `decelerating` | “放缓 -18%” |
| 其他 | `stable` | “平稳”（默认不显示） |

阈值 1.25 / 0.75 是“偏离 30 天值 ±25%”，来自 §2.8 的校准；要求 3 条 / 3 天是为了避免“一条爆肝记录 + 1 天跨度”就报加速。

### 5.4 边界一览

| 情况 | slow | fast | trend | 展示 |
| --- | --- | --- | --- | --- |
| 正常、近期加速 | 有 | 有 | accelerating | 主值 + 近期 + 趋势 |
| 正常、近期平稳 | 有 | 有 | stable | 主值 + 近期（不显示趋势） |
| 最近 8 天只有 1 条新快照 | 有 | `None` | `None` | 主值 + “近期样本不足” |
| 最近 3 天有 3 条，但跨度 <3 天 | 有 | 有 | `None` | 主值 + 近期 + “样本较少” |
| 最新一条异常 | 回退 | 按回退后算 | 按回退后算 | 主值 + “已按上一条计算” |
| 全部历史在 30 天内 | 最早一条 | 连续块 | 可能 accelerating | 主值跨度 <30 天，tooltip 如实显示 |
| 只有 2 条、间隔 5 天 | 有 | 有（跨度 5 天） | `None`（只有 2 条） | 主值 + 近期，不判趋势 |
| 只有 2 条、间隔 10 天 | 有 | `None`（缺口 >7 天，块内仅 1 条） | `None` | 主值 + “近期样本不足” |
| 只有 2 条、间隔 0.5 天 | 有 | `None`（跨度 <1 天） | `None` | 主值 + “近期样本不足” |

### 5.5 为什么不把 fast 混进主值

见 §2.6：α=0.3～0.7 的混合对 30 天 MAPE 基本没有改善，抖动 +21%～62%。fast 有 14%～33% 的高估，混进去只会让主值在“爆肝期”偏乐观、在“长草期”偏悲观。**主值负责“长期预期”，fast 负责“最近发生了什么”，两者用文案分层，不用算术混合。**

## 6. L2 展示

### 6.1 卡片

```
指级效率
11,374/天
```

- 文本格式不变：`formatExact(rate) + "/天"`；
- 降级仍为 `-`；
- **不加角标**、不改配色（本期决策）。

### 6.2 tooltip（三段）

正常示例：

```
近 30 天日均 11,374/天｜09-16 18:42 → 10-18 20:38（32.1 天，7 条）
近期节奏 15,023/天｜10-11 14:12 → 10-18 20:38（7.3 天，4 条）｜趋势 加速 +32%
窗口内最大缺口 15.7 天｜数据截止 10-18 20:38｜累计日均 9,520/天
```

规则：

- 第 1 段：slow + 起止 + 实际跨度 + 样本数（沿用 v1）；
- 第 2 段：fast 存在时显示；趋势只在 `accelerating/decelerating` 时追加；`stable` 不显示；`None` 时按 5.3 的文案说明；
- 第 3 段：`gap_days ≥ 7` 才显示缺口；数据截止时间始终显示；`stale_days ≥ 7` 追加“数据已 N 天未更新”；累计日均有值才显示；
- 慢窗口样本 <3 条时保留 v1 的“样本较少，仅供参考”；
- 总长度控制在 3 行以内；渲染方式按现有 `QToolTip` 验证（必要时用 `<br>`）。

降级示例：

```
指级效率：至少需要两条可换算的快照（当前 1 条）｜口径：近 30 天日均（绝对经验差 ÷ 实际跨度）
```

### 6.3 预期升级

> 2026-10-19 已把 30 天单值迁到「指挥官等级」卡片标题角标；2026-10-25 落地时确定
> 「近期情景」放在**「指挥官等级」tooltip**（`若维持近期节奏 X 天后升级`），
> 「指级效率」tooltip 只负责 slow / fast / trend / gap / stale，角标仍只放主值。

保持 30 天单值，另给近期情景：

```
预期升级 21.5 天（若维持近期节奏 16.3 天）
```

规则：

- `days_slow = remaining_exp / slow`；
- 仅当 `trend ∈ {accelerating, decelerating}` 且 `fast > 0` 时追加 `days_fast = remaining_exp / fast`；
- 满级返回“已满级”，无 slow 返回“预期升级 —”；
- 情景作为**一个 part** 返回（括号内），不要让外层 `｜` 再拆一次；
- **不写“16.3～21.5 天”**：实测 `[slow, fast]` 区间对实际值的覆盖率只有 17%～23%（7/14/30 天前瞻），它不是置信区间；写成两个情景更诚实。

### 6.4 文案约定

| 项 | 约定 |
| --- | --- |
| 主值 | `11,374/天`，`formatExact`，固定 `/天` |
| 近期 | `15,023/天`，`formatExact` |
| 趋势 | `加速 +32%` / `放缓 -18%`；百分比 = `round((ratio - 1) * 100)` |
| 缺口 | `15.7 天`，1 位小数 |
| 截止 | `10-18 20:38`，`MM-dd HH:mm`；跨年时用 `yyyy-MM-dd HH:mm` |
| 样本不足 | `近期样本不足` / `样本较少，暂不判断趋势`，不显示数字 |

| response | 合成阶跃后进入 ±10% 的天数 | 及时性 |
| trend precision / lift | 加速/放缓信号命中率 vs 基线 | 信号质量 |
| scenario coverage | `[slow, fast]` 覆盖实际值的比例 | 防止把情景误当区间 |

| --- | --- |

### 8.4 伪代码

```text
points, skipped, invalid = collectAbsolutePoints()
if 有效点 < 2: 返回降级

end = points[-1]
slow, start = windowRate(points, 30)          # v1 公式
block = currentBlock(points, gap=7, cap=14)
fast = endpointRate(block) if len(block) >= 2 and span(block) >= 1 else None

trend = None
if fast and slow > 0 and len(block) >= 3 and span(block) >= 3:
    ratio = fast / slow
    trend = "accelerating" if ratio >= 1.25 else \
            "decelerating" if ratio <= 0.75 else "stable"

gap = maxGap(points, start, end)
stale = max(0, floor((now - end) / 1 day))
return ExpEfficiency(slow, ..., fast, trend, gap, stale, invalid)
```

## 附录 A：回测口径与复现

- 数据：`data/AzurLaneStatisticalOfficeDB.db`，2026-10-18 23:xx，525 条原始 / 486 个自然日；
- 绝对经验：`absolute(L) = cum(L-1) + exp`，`cum` 来自 `commander_level_exp`；
- 同日去重：按 `statistics_date` 升序，同一天保留最后一条；
- walk-forward：origin `i` 只用 `points[:i+1]`；目标 `actual` 取 `t_i` 后首个 `span ≥ H` 的快照，`span ≤ H+3` 才收录；
- 样本：410～466 个 origin（不同 horizon）；
- 复现：`python tools/backtest_exp_efficiency.py --db ... --report ...`（P2 落地后）。

### A.1 候选估计器定义

| 名称 | 定义 |
| --- | --- |
| 30 天端点 | v1 公式，N=30 |
| 7 天端点 | v1 公式，N=7 |
| 长窗指数加权回归 | 120 天窗，半衰期 30 天，对 `A(t)` 做加权最小二乘 |
| 分段 EWMA（半衰期 30 天） | 对相邻段速率做半衰期 30 天的 EWMA，初值取 30 天端点 |

### A.2 抖动与响应

- 抖动：在全部 origin 上，相邻两次估值的 `|est_i - est_{i-1}|` 均值；
- 响应：合成 `A(t)`，前 60 天 5,000/天、之后 15,000/天、每日一条；从第 60 天起算，估值首次进入 `15,000 ±10%` 的天数。

## 附录 B：为什么“中间快照不增加 30 天平均的信息”

设 `A(t)` 精确，窗口 `[s,e]`：

```
R = (A(e) - A(s)) / (e - s)
```

`A(t_i)` 对任意 `s < t_i < e` 都不进入 `R` 的表达式。只要 `A(s)`、`A(e)` 正确，`R` 就是该窗口的真实平均；中间点不改变它。

如果对 `A(t)` 做回归，最小化的是残差平方和，得到的是“趋势斜率”或“加权平均速率”，不是 `R`。这两者在“速率恒定”时相等，在“速率变化”时不等——而速率变化正是我们要检测的东西。

因此 v2 的分工是：

- 窗口平均（主值）→ 端点差，不回归；
- 变化检测（趋势）→ 用中间点，但不混进主值；
- 数据质量（异常/缺口）→ 用中间点做校验，但不改变主值公式。
