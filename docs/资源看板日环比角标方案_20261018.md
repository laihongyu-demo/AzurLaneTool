## 3. 口径定义

### 3.1 推荐口径：严格自然日对比 + 断档退化为今日净额（v1.2）

```
今天 = T
最新有记录日 D = 结余链最后一行

若 D > T：
    灰色「数据异常」，提示最新记录晚于今天
若 D < T：
    灰色「未记录」，tooltip 保留最近一次日环比
若 D == T 且 T-1 也有日汇总行：
    delta = balance(T) - balance(T-1)              # basis = daily
若 D == T 且 T-1 无记录（含只有 T 一条记录）：
    delta = 今日收入 - 今日支出                     # basis = today_net（#37 口径 A）
    若今日为手填结余（balance_override 非空）：
        不给数字，角标 —，tooltip 标注
```

- 与卡片显示值**同源**：卡片结余就是 `balance(D)`；
- 连续两天仍用结余差，语义就是「今天比昨天」；
- **断档时为什么不用「今日结余 − 上次记录结余」**：那个差额跨了多天，会被读成「一天的变化」（#25 的顾虑）。今日净额只描述今天进出的钱，金额可逐笔核对；
- **今日净额与「今日结余 − 昨日结余」等价**：昨日结余按「今日结余 − 今日净额」回推，因此该值与用户要的差额一致，且不依赖昨日日汇总；
- **缺口日收支不计入**：上次记录日与今天之间的空缺日若有未记录收支，不属于今日净额，tooltip 显式写出缺口区间；
- 结余链本身已处理明细日 / 汇总日 / 锚点，因此不需要再区分 `detail_mode`；
- 不引入任何新的查询：在现有的 `getBalanceSeries` 结果上取最后两行，并多一次 `today()` 比较（见 §7）。

### 3.2 备选口径（供选择）

| 口径 | 定义 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 严格今日（v1.1 起采用）** | 只有 D == T 且 T-1 有记录时给数字；今日无记录显示「未记录」 | 语义最直白，角标只描述今天 | 每天首次记录前不显示数字 |
| B. 较上次记录 | D 与上一个有记录日 | 永远有值 | 若断档 3 天，标签会误读成"一天的变化" |
| C. 较 7 日均值 | D 结余 − 近 7 天均值 | 平滑 | 与"昨日"字面不符，用户难以核对 |
| **D. 较今日开始** | 当日净增（收入 − 支出） | 反映"今天赚了多少"，可逐笔核对 | 与"昨日"无关 |
| **A + D（v1.2 采用）** | 连续日走 A，断档 / 仅一天走 D | 既守住「不拿多日累计冒充昨日」，又不在断档时丢失变化信息 | tooltip 必须说明这是今日净额、缺口日收支不计入 |

> v1.2 采用 A + D：连续两天仍按 A，断档与仅一天记录改用 D。计划中列出的口径仍以 A 为主，D 作为断档兜底。

## 4. 展示设计

### 4.1 文案

| 情形 | 文案 | 颜色 |
| --- | --- | --- |
| 上涨 | `↑111` | 红 `#c62828` |
| 下降 | `↓111` | 绿 `#2e7d32` |
| 持平 / 今日净额 0 | `—` | 灰 `#757575` |
| 今日未记录 | `未记录` | 灰 `#757575` |
| 今日有记录但昨日断档 | A：`↑300` / `↓N` / `—`（今日净额） | 红 / 绿 / 灰 |
| 仅今天一天记录 | A：今日净额 | 红 / 绿 / 灰 |
| 今日为手填结余锚点（断档分支） | `—` | 灰 `#757575` |
| 最新记录晚于今天 | `数据异常` | 灰 `#757575` |
| 无数据（空表 / 缺表） | 不显示 | — |

- 千分符：≤ 9,999 用 `formatExact`（`↑1,111`）；≥ 10,000 用 `formatValue` 缩写（`↑12.3K`），与卡片刻度的缩写口径保持一致；
- 正负号：箭头已表达方向，数值不带 `+/-`；
- 箭头用 `↑` / `↓`（U+2191 / U+2193）；若字体缺字可退回 `^` / `v`。

### 4.2 位置

卡片结构是「标题 / 数值」两行。建议把数值行改为水平布局：

```
魔方
4.1K  ↑10
```

- 角标与数值**基线对齐**、右侧留 8px，卡片总高度不变；
- 不放在标题行，避免与标题抢空间。

### 4.3 tooltip

在现有提示后追加一段，保持可核对：

```
魔方：4,086（末次记录 2026-10-18 17:49:21）｜较昨日 +10（10-17 4,076 → 10-18 4,086）
```

| 情形 | 追加文案 |
| --- | --- |
| 上涨 / 下降（连续） | `｜较昨日 +10（10-17 4,076 → 10-18 4,086）` |
| 持平（连续） | `｜与昨日持平（10-17、10-18 均为 4,076）` |
| 今日未记录 | `｜今日未记录｜最近一次日环比 10-18 +11（10-17 4,076 → 10-18 4,087）` |
| 今日有记录但昨日断档 | `｜今日有记录，昨日（10-29）无记录；按今日净额 +300 计算（收入 300 − 支出 0，不含 10-27～10-29 收支）；上次记录 10-26 结余 4,040 → 今日 4,340，跨 4 天` |
| 断档且今日无收支 | `｜…；今日无收支；上次记录 10-26 结余 4,040 → 今日 4,040，跨 4 天` |
| 断档且有进有出相抵 | `｜…；今日净额 0（收入 300 − 支出 300，不含 … 收支）；…` |
| 断档且今日为手填结余锚点 | `｜…；今日为手填结余，不按净额比较（收入 300 − 支出 0，不含 … 收支）；…` |
| 仅今天一天数据 | `｜仅一天记录，按今日净额 +300 计算（收入 300 − 支出 0）` |
| 最新记录晚于今天 | `｜最新记录日期 2026-10-20 晚于今天，请检查数据` |
| 锚点日 | 上述文案后加 `（含手填结余）`，提醒该日结余是人为设定 |

- 断档分支的 tooltip 由 `ResourceService._buildTodayNetDelta()` 统一生成（断档说明 + 净额口径 + 上次记录跨度），避免角标与说明各写一套；
- 「今日无收支」只在收入与支出都为 0 时使用；有进有出但相抵时必须写「今日净额 0」，否则与后面的收支数字自相矛盾（真实数据 2026-10-30 即此情形：收入 300 − 支出 300）。

### 4.4 与卡片当前值的关系

- 若今天已录入且昨日也有记录 → 角标 = 今日结余 − 昨日结余（「今天比昨天」）；
- 若今天已录入但昨日断档（或只有今天一天） → 角标 = 今日收入 − 今日支出，tooltip 说明这是今日净额、缺口区间收支不计入；
- 若今天还没录入 → 灰色 `未记录`，不拿昨天的数字冒充今天；tooltip 保留最近一次日环比，供核对；
- 任何情况下都不再用更早的记录冒充昨天。

## 5. 边界与降级

| 场景 | 处理 |
| --- | --- |
| 无数据（表缺失 / 空表） | 卡片 `-`，不显示角标 |
| 只有今天一天记录 | A：`↑ / ↓ / —` 今日净额，tooltip 说明「仅一天记录，按今日净额计算」 |
| 只有历史一天记录、今天无记录 | `未记录` 灰，tooltip 说明「今日未记录｜仅一天记录」 |
| 今日无记录（D < T） | `未记录` 灰，tooltip 保留最近一次日环比 |
| 今日有记录但昨日断档 | A：`↑ / ↓ / —` 今日净额，tooltip 说明昨日无记录、上次记录日期与结余、缺口天数 |
| 断档且有进有出、净额 0 | `—` 灰，tooltip 写「今日净额 0（收入 … − 支出 …）」而不是「今日无收支」 |
| 缺口日有未记录收支 | 不计入今日净额；tooltip 写出缺口区间，明确「不含 … 收支」 |
| 今日为手填结余锚点（`balance_override` 非空） | `—` 灰，tooltip 标注「今日为手填结余，不按净额比较」；**仅断档分支**生效 |
| 上次记录日为锚点、今日非锚点 | 仍按今日净额给数字，tooltip 在上次记录处标注「含手填结余」 |
| 持平（连续两日） | `—` 灰，tooltip 说明与昨日持平 |
| 锚点日（连续两日） | 照常按结余差计算，tooltip 标注「含手填结余」 |
| 补录 / 撤销 / 删除明细后 | 结余链重算 → 角标自动随之变化（无需额外逻辑） |
| 未来日期的脏数据 | `数据异常` 灰，tooltip 提示检查数据 |

## 6. 实现设计

### 6.1 服务层

```python
@dataclass
class ResourceDailyDelta:
    delta: int                 # 正数上涨、负数下降、0 持平；含义随 basis 变化
    latest_date: str           # yyyy-MM-dd
    previous_date: str         # daily：前一日；today_net：上次记录日（仅一天记录时为空串）
    latest_balance: int
    previous_balance: int
    has_anchor: bool = False   # 参与比较的日期中是否有手填结余锚点
    basis: str = "daily"       # daily / today_net（#37）
    gap_days: int = 0          # today_net：上次记录距今的天数；daily：恒为 1
```

```python
@dataclass
class ResourceCardView:
    text: str
    tooltip: str
    delta: Optional[ResourceDailyDelta] = None   # None 仅表示未记录 / 数据异常 / 无数据
    badge_text: str = ""                          # 未记录 / 数据异常 也走这里
    badge_tone: str = ""                          # up / down / flat
```

- `ResourceService.getCardView()` 返回 `ResourceCardView`（**复用同一次结余扫描**，不新增查询）；
- `_buildDailyDelta(series, today)` 由调用方传入今天，便于测试跨天；连续日分支产出 `basis="daily"`，断档 / 仅一天分支委派给 `_buildTodayNetDelta()` 产出 `basis="today_net"`；
- `delta` 不再等于「两个结余之差」的场合必须看 `basis`，避免调用方误算；`isTodayNet` 属性是同一判断的语法糖；
- `getCardText()` / `getCardTooltip()` 保留，内部取 `getCardView()` 对应字段（对外行为不变）。

### 6.2 组件层

```python
class StatCard:
    def setBadge(self, text: str, tone: str) -> None:  # tone: up / down / flat
    def clearBadge(self) -> None
```

- 内部一个 `QLabel`，默认隐藏；`tone` 映射到三套 QSS 颜色；
- 数值行改为 `QHBoxLayout`（数值 + 弹性空白 + 角标），卡片高度与现有一致。

### 6.3 面板层

`StatisticsPanel.updateResourceStats()`：

```python
view = self._resource_service.getCardView(resource_type)
card.setValue(view.text)
card.setToolTip(view.tooltip)
badge_text = view.badge_text
badge_tone = view.badge_tone
if not badge_text and view.delta is not None:      # 兼容旧桩
    badge_text = view.delta.display_text
    badge_tone = view.delta.tone
if badge_text:
    card.setBadge(badge_text, badge_tone or DELTA_TONE_FLAT)
else:
    card.clearBadge()
```

跨天时 `StatisticsPanel.onActivated()` 在日期变化后调用一次 `updateResourceStats()`，让数字角标切换为「未记录」；同日切页不调用。

## 7. 性能

- 完全**复用** `getBalanceSeries` 的单次扫描（#14 修复后每资源仅 1 次），角标只是取最后两行做减法；
- 不新增 SQL、不新增连接；
- `updateResourceStats` 实测约 32.3 ms / 4 连接（#24 基准）；
- 跨天时 `StatisticsPanel.onActivated()` 多调用一次 `updateResourceStats`（一天一次，约 32–35 ms / 4 连接）；同日切页为 0。
