# 首次使用数据库自动初始化

> 日期：2026-11-15
> 关联 issue：#8
> 状态：已实现
> 范围：启动初始化、空白库模板结构、首次种子、打包数据目录

## 1. 背景与问题

#8 的目标是「没有数据库文件时自动建出空白模板，让初次使用可以直接运行」。改动前存在三个断层：

| 现状 | 证据（改动前） | 后果 |
|---|---|---|
| 缺库只打印警告，继续构造主窗口 | `main.py:36-49`：`if not os.path.exists(DEFAULT_DB_PATH)` 只 `print` 警告 | 首次查询才会建出一个**只有本次查询涉及的表**的空库 |
| 只有自有表有 DDL | `utils/db_schema.py:18-22` 只列资源 / 任务 / 贸易 / 活动脚本；图鉴 4 表与 `commander_info` 依赖历史库 | 图鉴 4 个面板、数据看板的收藏率 / 科技点、指级快照全部降级或提示缺表 |
| 等级经验基准不随库生成 | `commander_level_exp` 只建空表；200 行基准由 `tools/migrate_resource_statistics.py` 从 CSV 导入 | 指级效率、目标等级预测没有基准 |
| 打包后数据目录在临时解压目录 | `utils/constants.py:23-40`：`frozen` 时 `BASE_DIR = _MEIPASS`，`DATA_DIR = _MEIPASS/data` | 单文件 exe 新建的库在退出时随临时目录删除，自动建库等于无效 |

## 2. 目标与验收

- 删除 `data/` 后执行 `python main.py`：自动建出 `data/AzurLaneStatisticalOfficeDB.db`，6 个页签可用、不弹缺表提示；
- 首次自动写入：类型字典、任务定义、等级经验基准、`data/user.json`；
- 再次启动：不重复写种子，不覆盖已录入数据、人工修正与用户文件；
- 旧库（只有资源类表）启动时补齐图鉴 / 指挥官表，既有数据不变；
- 打包 exe 首次运行后库文件留在 exe 同目录 `data/`，退出不丢失。

## 3. 方案

### 3.1 分层落点

| 层 | 文件 | 职责 |
|---|---|---|
| 编排 | `utils/db_bootstrap.py`（新增） | 建父目录 / 库文件、按顺序调用建表、写种子、补 `user.json`、返回 `DatabaseInitReport` |
| 结构 | `utils/db_schema.py` | 新增 `ensureCodexSchema()` / `ensureCommanderSchema()`；抽 `_ensureCodexGroupColumns()` 复用补列回填 |
| DDL | `sql/CreateCodexTables.sql`（新增） | 图鉴 4 表 + `codex_group` 的 `date_edit` 触发器 |
| DDL | `sql/CreateCommanderTable.sql`（新增） | `commander_info` + `uq_commander_info_date` |
| 路径 | `utils/constants.py` | `DATA_DIR` 改为可写目录：源码用项目 `data/`，打包用 exe 同目录 `data/` |
| 入口 | `main.py` | 启动统一调用 `ensureDatabaseReady()`；新建库时弹一次「首次运行」说明 |
| 打包 | `build.spec` | `datas` 增加 `data/commander_level.csv` |

`ensureResourceStatisticsSchema()` 内部已按「旧结构升级 → 建表 → 空表播种类型字典」编排，本次不改其顺序；
等级经验改为「表为空才从 CSV 播种」，与 #21 的类型字典策略一致。

### 3.2 空白模板内容

建出 13 张业务表（全部 `IF NOT EXISTS`，已有表与数据不受影响）：

| 来源 | 表 | 首次是否写数据 |
|---|---|---|
| `CreateResourceStatisticsTables.sql` | `resource_daily` / `resource_transaction` / `resource_category` / `commander_level_exp` | 类型字典 43 项；等级经验 200 行 |
| `CreateCubeTaskTables.sql` | `cube_task` / `cube_task_completion` | 任务定义 24 项 |
| `CreateEventRecordTable.sql` | `event_record` | 空 |
| `CreateTradeLicenseTable.sql` | `trade_license_purchase` | 空 |
| `CreateCodexTables.sql` | `codex_group` / `codex_tp` / `codex_buff` / `awakening_of_mind` | 空表 |
| `CreateCommanderTable.sql` | `commander_info` | 空表 |

不建 `task_status` 与 `codex_group_copy*`：前者已无代码引用，后者只属于本机历史库的证据表。

`codex_group` 同时建 `update_codex_group_modtime` 触发器，保持与真实库一致的 `date_edit` 行为；
批量回填仍必须用 `utils.db_schema.suspendCodexGroupModtimeTrigger()` 包住。

### 3.3 种子与不覆盖规则

| 内容 | 规则 | 依据 |
|---|---|---|
| 类型字典 `resource_category` | 仅空表时播种 43 项 | 沿用 #21，保护用户改名 / 排序 / 停用 |
| 任务定义 `cube_task` | SQL 内 `ON CONFLICT DO UPDATE`，28 项定义以文件为准 | 既有口径 |
| 等级经验 `commander_level_exp` | 仅空表时从 `data/commander_level.csv` 播种 200 行；满级行经验为 NULL、文本进 `note` | 与迁移脚本 `importLevelExp` 同口径 |
| `user.json` | 仅文件缺失时生成：用户名 `指挥官`、开始日期取 `time_source.today()` | 执勤天数需要起点；已有文件不动 |
| 图鉴 / 指挥官数据 | 只建空表，不造示例数据 | 不伪造业务数据 |

CSV 缺失时跳过播种（`report.level_exp_rows == 0`），不阻塞其它表初始化；
CSV 存在但数据违反约束时抛 `DatabaseError`，避免写入半截基准。

### 3.4 打包数据目录

- `DATA_DIR`：源码运行 = `<项目>/data`；`frozen` = `<exe 目录>/data`，目录不存在时由初始化创建；
- 只读资源（`sql/`、`assets/`、`data/commander_level.csv`）仍从 `BASE_DIR`（`_MEIPASS`）读取；
- `build.spec` 的 `datas` 增加 `('data/commander_level.csv', 'data')`，否则打包版没有等级经验源文件；
- `repositories/user_repository.py` 默认路径由 `__file__` 推导改为 `DATA_DIR/user.json`，
  保证打包后读到的是初始化写出的 exe 同目录文件（源码运行两者本来就相同）。

### 3.5 启动提示

`main.py` 在新建数据库文件时，主窗口显示后弹一次 `QMessageBox.information`：库路径、新建表数量、
等级经验行数、`user.json` 路径，以及「图鉴为空，用『舰娘管理 → 新增舰娘』录入」。
旧库补表不弹窗，只打印「数据库就绪」。初始化失败只打印警告，不阻止启动（沿用原行为）。

## 4. 影响面

- 启动路径：`main.py` 不再区分「库存在 / 不存在」，统一走 `ensureDatabaseReady()`；
- 新增 SQL 两个文件，`build.spec` 已同步；
- `DATA_DIR` 在打包环境改变：此前单文件运行的数据落在 `_MEIPASS`，本来无法持久化，因此无需迁移；
  `UserRepository` 默认路径同步改为 `DATA_DIR/user.json`；
- 空库上主窗口不再出现「缺表」提示（表存在、数据为空），#28 的缺表降级逻辑保留给真正的旧库；
- 设置页、数据面板口径不变。

## 6. 风险与后续

- **`awakening_of_mind` 是空表**：觉醒材料与心智计算会显示 0。仓库内没有该表的权威种子，
  需要后续从游戏数据补 `SeedAwakeningOfMind.sql` 或导入入口；本次只保证结构可用。
- **图鉴批量导入没有入口**：历史 `codex_group` 由外部工具导入，仓库内没有导入功能；
  空白模板只能通过「新增舰娘」逐条录入。
- **`user.json` 只有默认值**：设置页编辑数据库路径 / user.json 仍待后续版本；
  用户可手工修改文件，启动不会覆盖。
- **首次提示是一次性模态框**：没有「不再提示」开关；只在真正新建库文件时出现。
- **打包数据目录语义变化**：exe 同目录 `data/` 需要可写；放在 Program Files 等只读目录时初始化会失败并打印警告。
