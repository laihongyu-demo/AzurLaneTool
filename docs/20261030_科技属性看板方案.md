# 科技属性看板方案（#36）

> 日期：2026-11-14
>
> 状态：已实现（2026-11-14；矩阵改造，全量 691 项通过）
>
> 关联：#36、#10、#12

## 1. 背景与目标

数据看板已有「科技点看板」，但没有科技属性的二维视图。原「科技属性看板」
只按 `buff_typ` 汇总，无法同时看出**哪个舰种缺哪类属性**。

本次将窗口改为 **`boost_typ`（增益目标舰种）× `buff_typ`（Buff 属性）矩阵**：

- 行：15 个 `boost_typ`；
- 列：9 个 `buff_typ`；
- 单元格：`已获得 buff_value / 总 buff_value`；
- 底部：按 `buff_typ` 汇总全部舰种的合计行；
- 无记录组合：`—`，不是 0。

入口不变：点击「科技点看板 → 剩余练级数量」卡片打开独立非模态窗口。

## 2. 数据来源与口径

数据表：`codex_buff`。

| 字段 | 含义 |
| --- | --- |
| `boost_typ` | 增益目标舰种 |
| `buff_typ` | Buff 属性类型 |
| `buff_value` | 属性加成值 |
| `buff_unlock` | 是否已解锁（Y / N） |

单元格口径：

| 项 | 公式 | 说明 |
| --- | --- | --- |
| 已获得 | `SUM(buff_value) WHERE buff_unlock='Y'` | 该舰种 × 属性下已解锁的加成合计 |
| 总 | `SUM(buff_value)` | 该舰种 × 属性下所有记录的加成合计 |
| 记录数 | `COUNT(*)` | 只用于区分「无记录」与「有记录但未解锁」，不在主界面展示 |
| 完成率 | 已获得 / 总 | 0–100%，总值为 0 时为 0.0% |

**不做行合计**：同一舰种下把耐久、炮击、雷击等不同属性相加没有业务含义。
**做列合计**：同一 `buff_typ` 跨舰种相加有意义，底部合计行保留原 9 项汇总视图的信息。

### 2.1 2026-11-14 只读实测

- `codex_buff` 2,591 行；
- 15 个 `boost_typ` × 9 个 `buff_typ` = 135 格；
- 84 格有记录，51 格为空；
- 示例：
  - 驱逐 × 耐久：238 / 258，247 条记录；
  - 战列 × 炮击：57 / 86，67 条记录；
  - 风帆 × 机动：0 / 5，5 条记录但均未解锁；
  - 驱逐 × 航空：无记录。

`0/5` 与 `—` 必须区分：前者有记录但未解锁，后者没有记录。

## 4. SQL 口径

`sql/GetCodexBuffMatrixByBoostTypAndBuffTyp.sql`：

```sql
SELECT
    TRIM(boost_typ) AS boost_typ,
    TRIM(buff_typ) AS buff_typ,
    COALESCE(SUM(buff_value), 0) AS total_value,
    COALESCE(SUM(CASE WHEN buff_unlock = 'Y' THEN buff_value ELSE 0 END), 0) AS unlocked_value,
    COUNT(*) AS record_count
FROM codex_buff
WHERE boost_typ IS NOT NULL AND TRIM(boost_typ) <> ''
  AND buff_typ  IS NOT NULL AND TRIM(buff_typ)  <> ''
GROUP BY TRIM(boost_typ), TRIM(buff_typ);
```

只读，不修改 `codex_buff`。84 行结果在 2,591 行数据量下无性能压力。

## 5. 窗口设计

- 标题：`科技属性看板`；非模态，打开期间可继续操作主界面。
- 表格：
  - 16 行：15 个 `BOOST_TYPS` + `合计`；
  - 10 列：`舰种` + 9 个 `BUFF_TYPS`；
  - 单元格：`已获得/总`，如 `238/258`；
  - 空组合：灰色 `—`；
  - 已完成组合：浅绿底 + 深绿字（`已获得 = 总` 且总值大于 0）；
  - 合计行：加粗、浅灰底，按 `buff_typ` 汇总全部舰种；
  - 行/列顺序固定为白名单顺序，不排序。
- 单元格 tooltip：
  - `驱逐 × 耐久：已获得 238 / 总 258（92.2%）；247 条记录。`
  - `风帆 × 机动：已获得 0 / 总 5（0.0%）；5 条记录，均未解锁。`
  - `驱逐 × 航空：暂无记录。`
- 窗口默认约 `1000×720`，最小 `900×560`；列宽按内容自适应，小屏时表格内部滚动。
- 单元格数值省略千分符（如 `1416/1472`），tooltip 使用带千分符的精确值。

## 6. 边界与降级

| 场景 | 处理 |
| --- | --- |
| `codex_buff` 缺表 / 缺列 | 返回 15×9 全空矩阵；窗口显示 `—` 与 0 合计，不弹模态框 |
| 某组合无记录 | 单元格 `—` |
| 某组合有记录但全未解锁 | `0/总`，tooltip 注明「均未解锁」 |
| 白名单外 `boost_typ` / `buff_typ` | 不进入矩阵；Service 只按白名单补齐 |
| `buff_value` 为空 | `SUM` 忽略空值 |
| 窗口打开期间数据变化 | 每次 `showEvent` 重新聚合 |

## 8. 风险与后续

- 矩阵 16×10 比原 9 行表更宽；真实窗口的列宽、字号、滚动条需要人工确认。
- 空组合较多（51/135），`—` 的灰色权重不能压过有效数据。
- 行合计不可加；如未来需要「舰种总体完成度」，必须另定口径，不能直接横向求和。
- 当前不做单元格点击下钻（舰娘列表）；如需按组合查看具体舰娘，另开需求。
