# 科技属性看板方案（#36）

> 日期：2026-10-30  
> 状态：已实现（2026-10-30；新增 6 例，全量测试结果见交付记录）  
> 关联：#36、#10、#12

## 1. 背景与目标

数据看板已有「科技点看板」，但没有科技属性（`codex_buff`）的汇总视图。
用户期望看到**各 Buff 属性类型（`buff_typ`）的 `buff_value` 汇总值**，
而不是条目数量，也不是按增益目标舰种（`boost_typ`）汇总。

UI 入口：点击「科技点看板 → 剩余练级数量」卡片，打开独立的非模态
「科技属性看板」窗口。

## 2. 数据来源与口径

数据表：`codex_buff`。

| 字段 | 含义 |
| --- | --- |
| `buff_typ` | Buff 属性类型（耐久 / 炮击 / 雷击 / 航空 / 防空 / 装填 / 命中 / 机动 / 反潜） |
| `buff_value` | 属性加成值 |
| `buff_unlock` | 是否已解锁（Y / N） |

按 `buff_typ` 分组的两个汇总值：

| 列 | 公式 | 说明 |
| --- | --- | --- |
| 已获得汇总值（主） | `SUM(buff_value) WHERE buff_unlock='Y'` | 已解锁记录提供的属性加成合计 |
| 总汇总值 | `SUM(buff_value)` | 该属性所有记录的理论加成合计 |
| 完成率 | 已获得 / 总 | 0–100%，总值为 0 时为 0.0% |

不再展示：
- `COUNT(*)` 条目数；
- 按 `boost_typ`（增益目标舰种）的汇总；
- 全解锁舰船数。

## 4. SQL 口径

`sql/GetCodexBuffProgressByBuffTyp.sql`：

```sql
SELECT
    TRIM(buff_typ) AS buff_typ,
    COALESCE(SUM(buff_value), 0) AS total_value,
    COALESCE(SUM(CASE WHEN buff_unlock = 'Y' THEN buff_value ELSE 0 END), 0) AS unlocked_value
FROM codex_buff
WHERE buff_typ IS NOT NULL AND TRIM(buff_typ) <> ''
GROUP BY TRIM(buff_typ);
```

- 只读，不修改 `codex_buff`；
- 同一 `buff_typ` 下的 `buff_value` 可相加（例如耐久 +1/+2 都是耐久加成）；
- 空 `buff_typ` 不进入结果，Service 也不会把它补进白名单。

## 5. 窗口设计

- 标题：`科技属性看板`；非模态，打开期间可继续操作主界面。
- 顶部说明：按 `buff_typ` 汇总 `buff_value`，主值为已获得汇总值。
- 表格 4 列：Buff 属性、已获得汇总值、总汇总值、完成率。
- 行顺序固定为 `options.BUFF_TYPS` 白名单顺序；某属性无数据时显示 0，不隐藏行。
- 每个单元格 tooltip 给出口径与完成率。
- 缺表 / 缺列：Service 返回 9 项全 0；其他数据库错误由窗口显示
  「数据库错误：…」，不弹模态框。

## 6. 边界与降级

| 场景 | 处理 |
| --- | --- |
| `codex_buff` 缺表 / 缺列 | 9 项全 0，窗口仍可打开 |
| 某 `buff_typ` 没有记录 | 该行显示 0 / 0，完成率 0.0% |
| 白名单外出现 `buff_typ` | 不进入主表；当前数据 0 条，后续如出现需在 Service 记录/提示 |
| `buff_value` 为空 | SQL `SUM` 忽略空值 |
| 同一属性多条记录 | 全部 `buff_value` 相加；已获得只加 `buff_unlock='Y'` 的记录 |
| 窗口打开期间数据变化 | 每次 `showEvent` 重新聚合 |

## 9. 风险与后续

- 「总汇总值」是该属性理论加成合计，不代表游戏内当前面板值；只用于完成度参考。
- 同类属性内的 `buff_value` 相加是合理的；不同属性之间不应再相加，因此不提供跨属性总计。
- 当前窗口不做排序 / 筛选；9 行足够。
- 白名单外 `buff_typ` 目前静默忽略；如后续数据出现未知值，应在 Service 增加提示或日志。
