# 「指挥官等级」卡片预计升级角标方案

> 版本 v1.0（已实现，2026-10-19）
> 关联：#14（看板四张卡）、#16（指级效率）、#23（指级效率 v2，未实现）
> 目标：把 tooltip 里的「预期升级 X 天」迁到卡片表面，同时不撑宽本就很长的等级/经验数值行。

## 0. 结论

| 项 | 结论 |
| --- | --- |
| 位置 | **标题行**，紧跟「指挥官等级」右侧，标题与角标作为一组居中 |
| 文案 | 正常：`预计 22.0 天后升级`；满级：`已满级`；经验已满但未满级：`可升级`；无法估算：不显示 |
| 配色 | 信息型：蓝字 `#1565c0` / 浅蓝底 `#e3f2fd`；满级：绿字 `#2e7d32` / 浅绿底 `#e8f5e9` |
| 关键理由 | 数值行 360 px 已占满 390 px 卡宽；标题 + 角标只占 205 px，标题行仍有 155 px 余量 |
| tooltip | 不再重复预计升级天数；效率不足时补一句「暂无法预估升级天数」 |

卡片形态：

```
指挥官等级  [预计 22.0 天后升级]
163（105,302/354,350）
```

## 1. 背景

#14 验收时把「预期升级 X 天」放进了「指挥官等级」卡的 tooltip。实际使用中这段信息需要悬停才能看到，而它又是判断“还要肝多久”的核心信息，因此希望常驻在卡片上。

限制在于卡片主值已经很长：`163（105,302/354,350）` 使用 28 px 粗体，横向空间几乎用满；直接把角标加到数值右侧会撑宽整行五张卡。

---

## 2. 尺寸实测与位置分析

测量环境：Windows / Qt 5.15.11 / 96 DPI / Microsoft YaHei UI，`StatCard` 默认字号（标题 14 px、数值 28 px、内边距 15 px）。不同字体与 DPI 下像素值会变化，但“数值行没有余量、标题行有余量”的结论不变。

### 2.1 现有卡片宽度

| 项 | 宽度 |
| --- | ---: |
| 数值 `163（105,302/354,350）` | 360 px |
| 卡片内容宽（数值 + 左右内边距） | 390 px |
| 标题「指挥官等级」 | 70 px |
| 标题 + 角标（含 6 px 间距） | 205 px |
| 数值行剩余空间 | **0 px** |
| 标题行剩余空间 | **155 px** |

### 2.2 候选位置对比

| 位置 | 单卡宽度变化 | 五卡宽度之和（基线） | 评价 |
| --- | ---: | ---: | --- |
| **标题行（采用）** | 390 → 390 px | 876 → 876 px | 不撑宽、不增高；标题与角标形成一个语义组 |
| 数值右侧 | 390 → 512 px（+122 px） | 876 → 998 px（+122 px） | 在现状基础上再 +122 px，整行会被迫加宽或挤压；角标还会和主值抢视觉 |
| 数值下方另起一行 | 宽度不变 | 876 → 876 px | 需要增加卡片高度，五张卡一起变高，且角标离标题更远 |

数值右侧被否决的决定性数据：单卡多出 122 px，五卡宽度之和 876 → 998 px；资源卡带日环比角标时则是 954 → 1076 px。标题行方案与改动前完全一致，不增加任何宽度。1024 默认窗口扣除主窗口、面板与分组内边距后约 920 px；954 的现状在 1024 窗口下已经偏紧，1076 会明显溢出；标题行方案至少不会让现状变差。即使窗口能拉宽，主值 + 角标挤在同一行也会让 28 px 的数字失去焦点。

### 2.3 标题行内部怎么放

采用“标题 + 角标”作为一组居中：

```
[      指挥官等级  [预计 22.0 天后升级]      ]
[      163（105,302/354,350）              ]
```

- 角标只占标题行的 155 px 余量，卡片宽高都不变；
- 标题本身会比卡片中心略向左（约 68 px），但“标题 + 角标”整体仍居中，阅读时是一个整体；
- 备选“标题保持居中、角标贴右上角”也能保持宽度，但角标会远离标题、悬在空白处，像另一个指标，故未采用。

### 2.4 高度

加角标前后 `StatCard.sizeHint()` 均为 **390 × 100 px**；标题行高度仍为 20 px（角标 19 px），五张卡的数值基线保持一致。

## 3. 配色

### 3.1 语义冲突

现有角标颜色已经被“魔方 / 红尖尖日环比”占用：

| 颜色 | 现有语义 |
| --- | --- |
| 红 `#c62828` | 资源上涨 |
| 绿 `#2e7d32` | 资源下降 |
| 灰 `#757575` | 持平 / 未记录 / 无法比较 |

预计升级天数不是涨跌方向：它既不表示“变好”，也不表示“变差”。如果沿用红/绿，会被误读成资源卡的方向角标；如果沿用灰，又会像“无数据 / 不可用”。

### 3.2 采用颜色

| 状态 | 文字 | 背景 | 对比度 | 说明 |
| --- | --- | --- | ---: | --- |
| 预计 X 天后升级 / 可升级 | `#1565c0` | `#e3f2fd` | 5.03:1 | 信息蓝；`commander_exp_panel` 的模式标签已用同色，功能区内一致 |
| 已满级 | `#2e7d32` | `#e8f5e9` | 4.56:1 | 完成态绿；只在“真正满级”时出现，和资源下降的绿靠文案区分 |

两种组合都达到 WCAG AA 正文对比度（≥ 4.5:1）。也评估过琥珀色（`#b26a00` / `#fff3e0`，3.86:1）：既暗示“警告”，对比度也不足，未采用。

浅色底 + 9 px 圆角让角标成为标签，而不是标题的一部分；它比 14 px 灰色标题更醒目，但仍明显弱于 28 px 主值。

## 4. 展示规则

| 情形 | 角标 | 配色 | 说明 |
| --- | --- | --- | --- |
| 有快照、有基准、效率 > 0 | `预计 22.0 天后升级` | info | 30 天日均效率估算，保留 1 位小数 |
| 本级经验已满、等级 < 200 | `可升级` | info | 不再误报「已满级」 |
| 等级 = 200 | `已满级` | success | 优先于基准缺失判断 |
| 无快照 | 不显示 | — | 卡片主值为 `-` |
| 等级基准缺失（剩余经验未知） | 不显示 | — | tooltip 已有「升级所需经验未知」 |
| 只有一条快照 / 效率为 0 | 不显示 | — | tooltip 补「暂无法预估升级天数（指级效率数据不足）」 |
| 刷新异常 | 不显示 | — | `_showError()` 主动清除，避免旧角标挂在「错误」旁边 |

其他约定：

- 预计升级仍取 **近 30 天日均**，与「指级效率」卡同源；本期不引入 #23 的近期情景；
- tooltip 不再包含预计升级天数，避免同一信息出现两次；
- 快照增删改后由 `updateCommanderStats()` 刷新角标，不需要额外的定时器；
- 角标不改变点击行为：点击角标仍会打开「指级经验」窗口（QLabel 不拦截鼠标事件）。

## 5. 实现

### 5.1 服务层

`services/commander_service.py`：

- 新增 `CommanderLevelBadge(text, tone)`；
- 新增 `getCommanderLevelCardBadge()`，只读取最新快照与等级基准；
- 私有 `_buildUpgradeBadge(level, remaining_exp)` 统一状态判断：

```python
if level >= COMMANDER_LEVEL_MAX:  return "已满级", "success"
if remaining_exp is None:         return "", ""
if remaining_exp <= 0:            return "可升级", "info"
rate = getExpEfficiency().rate_per_day
if not rate:                      return "", ""
return f"预计升级 {remaining_exp / rate:.1f} 天", "info"
```

- `getCommanderLevelCardTooltip()` 删除原 `_formatUpgradeEstimate()` 片段；角标为空且仍可估算时追加原因。

### 5.2 组件层

`views/widgets/stat_card.py`：

- 标题由单独 `QLabel` 改为「弹性空白 + 标题 + 标题角标 + 弹性空白」的 `QHBoxLayout`；
- 新增 `TITLE_BADGE_TONE_STYLES`（info / success）；
- 新增 `setTitleBadge()` / `clearTitleBadge()` / `titleBadgeText()` / `titleBadgeTone()`；
- 数值右侧原有的 `setBadge()` 与红涨绿跌样式保持不变，两套角标互不影响。

### 5.3 面板层

`views/widgets/statistics_panel.py`：

- `updateCommanderStats()` 读取 `getCommanderLevelCardBadge()`，有文案则 `setTitleBadge()`，否则 `clearTitleBadge()`；
- `_showError()` 清除指挥官等级卡角标。

### 5.4 涉及文件

| 文件 | 变更 |
| --- | --- |
| `services/commander_service.py` | 角标数据、状态判断、tooltip 去重 |
| `views/widgets/stat_card.py` | 标题行布局与标题角标 API / 配色 |
| `views/widgets/statistics_panel.py` | 角标接线、错误降级清除 |
| `tests/test_commander_service.py` | 角标状态与 tooltip 测试 |
| `tests/test_commander_panel.py` | 面板接线与错误清除测试 |
| `tests/test_time_refresh.py` | 面板桩补 `getCommanderLevelCardBadge()` |
