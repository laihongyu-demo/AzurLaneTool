# 设置页与类型字典自助维护方案（#21）

- 日期：2026-10-19
- 关联：[#21](https://github.com/laihongyu-demo/AzurLaneTool/issues/21)（类型字典自助维护）、#17（资源录入与编辑）
- 结论：本轮新增主窗口「设置」页签，先落地类型字典维护；数据库路径自定义、user.json 编辑另开 issue。

## 1. 背景

常规录入的类型下拉来自 `resource_category`，此前新增 / 改名 / 排序 / 停用都必须直接写库。

同时存在一个先决问题：`sql/SeedResourceCategories.sql` 每次启动都以
`ON CONFLICT(resource_type, direction, name) DO UPDATE SET sort_order = excluded.sort_order`
回写顺序。只要自助维护上线，用户调过的顺序、改过的名称都会在下次启动被覆盖。

## 2. 方案

### 2.1 入口

- 主窗口页签从 3 个增加到 4 个：数据看板 / 舰娘管理 / 资源统计 / 设置。
- `文件 → 设置…`（`Ctrl+,`）作为快捷入口，切到设置页签。
- 设置页按分组块组织，本轮只有「类型字典」；后续的数据库路径、user.json 编辑按同样方式追加分组。
- 设置页不持有时间上下文：`syncTimeContext()` 为空实现，`onActivated()` / `refreshData()` 只重读类型字典（2 条小查询）。

### 2.2 库结构

`resource_category` 增加启用状态列：

```sql
is_active INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0, 1))
```

- 全新库：由 `sql/CreateResourceStatisticsTables.sql` 直接建出。
- 已有库：`utils/db_schema.py` 的 `_upgradeResourceCategorySchema()` 以「列是否存在」为前提补列，默认全部启用，可重复执行。

### 2.3 种子策略

`ensureResourceStatisticsSchema()` 改为在 `resource_category` 为空时才执行 `SeedResourceCategories.sql`
（`_seedCategoriesIfEmpty()`），脚本内的冲突处理同时降级为 `DO NOTHING`。

- 已有字典的库：启动完全不动名称、顺序、停用状态。
- 全新库：照常写入 41 条默认类型。
- 代价：以后新增默认类型不会自动补进老库，需要一次性迁移脚本；本轮不涉及。

### 2.4 业务口径

| 操作 | 行为 | 约束 |
|---|---|---|
| 新增 | 追加到当前「资源 + 方向」分组末尾（`sort_order = max + 10`） | 名称去掉首尾空白；同组重名（含已停用）拒绝；最长 20 字 |
| 改名 | 更新字典名称，并在**同一事务**内把 `resource_transaction.category` 由旧名同步为新名 | 同组重名拒绝；名称未变化不写库 |
| 上移 / 下移 | 与相邻项交换位置，整组重排序号为 10、20、30…… | 已在首 / 末位只回状态栏提示，不写库 |
| 停用 / 启用 | 只改 `is_active`；停用项不出现在常规录入下拉 | 每组至少保留一个启用中的类型 |

明确不做：

- 不提供删除类型（停用已覆盖「不想再用」的场景，也避免种子或历史明细产生孤儿）。
- 不提供拖拽排序（按钮实现简单、可单测；后续确有需要再评估）。
- 停用不影响历史明细与统计：明细仍按原名保留，`resource_transaction` 不做任何改写。

### 2.5 分层落点

| 层 | 文件 | 内容 |
|---|---|---|
| SQL | `sql/CreateResourceStatisticsTables.sql` | `resource_category.is_active` |
| SQL | `sql/SeedResourceCategories.sql` | 冲突处理改为 `DO NOTHING`，注释说明只在空表执行 |
| Utils | `utils/db_schema.py` | `_upgradeResourceCategorySchema()`、`_seedCategoriesIfEmpty()` |
| Model | `models/resource_model.py` | `ResourceCategoryModel.is_active` |
| Repository | `repositories/resource_repository.py` | `findCategories(include_inactive)`、`findCategoryById/Name`、`countTransactionsByCategories`、`insertCategory`、`updateCategoryName`、`updateTransactionCategory`、`updateCategoryActive`、`updateCategorySortOrders` |
| Service | `services/resource_category_service.py` | `CategoryEntry`、`CategoryWriteResult`、`ResourceCategoryService`（查询 / 新增 / 改名 / 移动 / 启停 + 校验） |
| View | `views/widgets/settings_panel.py` | `SettingsPanel`、`CategoryDictionarySection` |
| View | `views/main_window.py` | 第 4 个页签、文件菜单「设置…」、结果与联动信号 |
| View | `views/widgets/resource_management_panel.py`、`cube_task_board_panel.py` | `refreshEntryCategories()`，类型字典变更后刷新两个常规录入下拉 |

改名事务由 Service 用 `DatabaseContext` 编排，Repository 只接收 `conn` 执行 SQL，符合分层约定。

## 3. 界面

- 顶部：资源（魔方 / 红尖尖）、方向（支出 / 收入）下拉；方向顺序与常规录入一致。
- 列表：`序号. 类型名（已停用） · N 笔明细`；停用行灰显，tooltip 显示方向、状态、明细笔数、排序序号。
- 右侧：新增、改名、上移、下移、停用 / 启用；未选中行时后四个按钮禁用，首 / 末行再分别禁用上移 / 下移。
- 写操作后：刷新列表并尽量保持选中；发出 `categoriesChanged`（主窗口据此刷新常规录入下拉）与 `resultReady`（主窗口状态栏）。
- 首 / 末位移动、名称未变化等「无需写库」的结果只进状态栏，不弹窗；校验失败弹警告，数据库错误弹错误框。

```powershell
# 新增用例：服务 27 项 + 设置页 17 项
python -m unittest tests.test_resource_category_service tests.test_settings_panel -v

# 建表引导与录入过滤
python -m unittest tests.test_db_schema tests.test_resource_entry_service tests.test_regular_entry_panel -v

# 全量
python -m unittest discover -s tests
```

- 全量结果：438 项通过（改动前基线 390 项；新增 48 项）。
- 真实库只读核对：把 `data/AzurLaneStatisticalOfficeDB.db` 复制到临时目录后建窗，确认
  页签为「数据看板 / 舰娘管理 / 资源统计 / 设置」、文件菜单含「设置…」、设置页列出 7 条魔方支出类型、
  常规录入下拉 23 项、`refreshData()` 与菜单切页正常；原库未被修改。
- 未验证：真实窗口下的视觉与交互（列表宽度、按钮布局、弹窗文案）需要人工确认。

## 5. 风险与后续

- 老库首次启动会补 `is_active` 列（DDL，仅加列）。升级失败时设置页与录入下拉会因缺列降级：
  `listCategories()` 返回空、录入下拉提示加载失败；建议升级前备份数据库。
- 种子「只在空表执行」意味着默认类型不会随版本自动增补；以后要加默认类型，需写一次性迁移并先在临时库演练。
- 类型名称最长 20 字、按原样比较（区分大小写与符号），未做同音 / 近似名提示。
- 后续 issue：数据库路径自定义、`data/user.json` 编辑，均计划挂在设置页下。
